# Node quick start

[简体中文](快速开始.md) · English

For source installation, start with the [README](../../README.en.md#quick-start). This guide installs a **Node 0.8.2** wheel on the **Node device**, enrolls it with **Hub 0.9.3**, and hands off the resource. Hub must already be running. Managed mode creates a new browser per session.

## Before you start

Obtain the following from the Hub deployer or release maintainer:

| Material | Requirement |
| --- | --- |
| Hub base URL | Reachable from Node; no `/mcp`, `/v2`, or `/health` suffix |
| Original `enrollment.token` | The same UTF-8 single-line file generated by Hub and currently read by it |
| Node wheel | `runbridge_node-0.8.2-py3-none-any.whl`, saved with the attachment in `~/Downloads/` |

Prepare Python **3.14.x**, global [uv](https://docs.astral.sh/uv/getting-started/installation/), and a system able to run Chromium. See [Python](https://www.python.org/downloads/) and [Playwright requirements](https://playwright.dev/python/docs/intro#system-requirements).

From Node, check the actual Hub address:

```bash
curl --fail http://192.168.50.10:8787/health
```

Replace the example address. Expect `{"status":"ok","protocol_version":2}`. `127.0.0.1` on Node refers to Node itself.

## Install and save enrollment material

In a new deployment directory:

```bash
mkdir -p ~/runbridge-node
cd ~/runbridge-node
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_node-0.8.2-py3-none-any.whl[playwright]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
umask 077
mkdir -p .runbridge
cp -n ~/Downloads/enrollment.token .runbridge/enrollment.token
chmod 600 .runbridge/enrollment.token
```

`[playwright]` installs Python Playwright **1.63.0** into this `.venv`. Packages in other environments are not shared automatically. Preserve enrollment text as received, without quotes, JSON, `Bearer `, or `token=`. Existing deployments retain their own identity and files.

## Prepare Chromium and YAML

Use this environment's Python Playwright to prepare the matching browser and system dependencies according to the [official browser guide](https://playwright.dev/python/docs/browsers). Reuse an existing matching installation if available. Installation and execution must use the same user and browser cache. No separate Node.js/npm installation is needed; Node does not download browsers on startup.

Create `node.yaml` with the actual Hub URL:

```yaml
hub_url: http://192.168.50.10:8787
enrollment_token_file: .runbridge/enrollment.token
tools:
  playwright: {}
```

Defaults are YAML format `2`, host name as the initial display name, identity `.runbridge/node.json`, resource `chromium`, managed headless mode, and a `20000` ms launch timeout. Relative paths resolve from the **YAML directory**; `~` and `$HOME` are not expanded.

For a custom browser or existing login environment, select `channel`, `executable_path`, or borrowed mode using [parameters](../reference/参数详解.en.md). Keep the modes' fields separate. See the [annotated YAML](../reference/examples/Node启动配置.en.yaml).

## Start and verify connection

```bash
.venv/bin/runbridge-node run --settings node.yaml
```

Keep the terminal running. Initial startup creates a stable identity, enrolls, probes the browser, and connects. No prior `register` is needed. Hand off the logged `node_id`, resource ID, and mode. Use Hub's dashboard to check **ONLINE**, fresh capabilities, and actual resource **READY / FREE**. ONLINE alone proves only the connection.

## Hub allocates the lease

Node 0.8.2 pairs with Hub 0.9.3. Node's `grant` / `revoke` commands have been removed. Clients use Hub's claim credential, claim the entire Node, and save the five-field `access_config` as JSON or YAML. The Node process does not receive the Hub claim credential.

The default Node lease is 3600 seconds, default maximum 86400, and default idle timeout 600; the last two are Hub settings. `inspect` is optional client-side diagnostics, not a required enrollment or authorization step.

## Verify a real browser session

This optional diagnostic starts and cleans up Chromium. First have the client claim this Node through the [Hub client guide](https://github.com/Pegasus-Yang/Run-Bridge-Hub/blob/main/doc/user-guide/调用方对接与使用.en.md) and save the real file as `.runbridge/access.json`. Do not give the same lease to another active task.

With Node still running, use another terminal:

```bash
.venv/bin/runbridge-node session create --access-file .runbridge/access.json > .runbridge/session.json
```

Only after a successful response, read the actual ID and query and close it:

```bash
rb_session_id=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/session.json").read_text())["session_id"])')
.venv/bin/runbridge-node session get "$rb_session_id" --access-file .runbridge/access.json
.venv/bin/runbridge-node session close "$rb_session_id" --access-file .runbridge/access.json
```

Expect `READY` or `ACTIVE`, an actual `about:blank` page in `objects.pages`, and `cleanup=COMPLETE` on close. Optional `inspect` should show READY/FREE afterward. Headless mode does not open a visible window. Defaults are tool `playwright`, resource `chromium`, and session lease 300 seconds; see [session options](../reference/参数详解.en.md#session-commands) to change them. `session.json` is a response, not startup configuration.

## Handoff, restart, and cleanup

Give clients the Node ID, resource ID, mode, and installed version. For borrowed Chrome, also identify the exact authorized page URL. Keep `node.json`, enrollment material, local endpoints, and profiles on the device. After the diagnostic, release the Node lease through Hub and confirm `RELEASED`; browser `FREE` alone does not return Node.

For normal shutdown, have clients release sessions, then use Ctrl+C in the Node terminal. Restart with the same YAML and identity. After enrollment, `enrollment_token_file` may be omitted; keeping it performs idempotent enrollment confirmation. Do not delete identity files to fix networking.

At batch completion, cancellation, or failure, clients use the original `access_token` for `DELETE /v1/grants/{grant_id}`. `RELEASING` means cleanup is pending; `RELEASED` returns ownership; `QUARANTINED` still blocks new claims. An invalidated token can query its original lease or repeat release, but cannot take over another lease. See the [Hub lease API](https://github.com/Pegasus-Yang/Run-Bridge-Hub/blob/main/doc/reference/Node使用权租约接口.en.md).

## Common problems

| Symptom | Check |
| --- | --- |
| Health unreachable | Actual URL, bind address, network, and proxy; contact the Hub deployer |
| Enrollment 401 | Original single-line file, permissions, and paired versions |
| Invalid YAML | Space indentation, object at top level, snake_case fields, and [parameters](../reference/参数详解.en.md) |
| ONLINE but UNAVAILABLE | Browser/cache/system libraries/desktop permissions under the same user and `.venv` |
| No browser window | Default headless mode; use frames or set `headless: false` with a working desktop |
| Missing `grant` / `revoke` | Claim and release through Hub; do not add Hub tokens to Node identity |
| BUSY | Query and release your existing session instead of creating another |
| UNKNOWN cleanup | Preserve activity records and follow [operations](../deployment/运行与排障.en.md) |
| Another Node disconnects on restart | Ensure distinct identity files |
| Identity belongs to another Hub | Decide whether this is a Hub migration or a new environment before changing the URL |
| Borrowed connection or keychain prompt | Follow [Chrome reuse](Chrome复用快速开始.en.md) and [credential handling](../deployment/浏览器凭据与测试数据.en.md) |

See [deployment](../deployment/部署与运行.en.md) and [operations](../deployment/运行与排障.en.md) for long-term use. Some CLI messages remain Chinese.
