# Node 浏览器画面采集

[文档导航](../README.md) · [部署 Node](../deployment/部署与运行.md) · [Chrome 复用](Chrome复用快速开始.md) · [配置参考](../reference/部署配置与凭据.md)

本指南说明 Node 所有者如何启用和核对已有 Chrome 的 PNG 采集。调用方的订阅、目标选择和展示接口由 Hub 项目的画面指南维护。

## 1. 选择采集路线

| 资源 | Node 所有者准备 |
| --- | --- |
| 已有 Chrome | 明确授权的本机实例；Node 安装 visual extra，在活动会话期间采集并上传 |
| 受管理 MCP 页面 | 按受管理指南准备运行时；探测上报 managed_visual=cdp-png，画面由服务端同页采集 |
| 普通 SDK 受管理会话 | 当前没有独立画面流；安装 visual 不改变这一点 |

## 2. 为已有 Chrome 安装扩展

正常停止 Node 后，在原部署环境安装同版本带 extra 的 wheel：

```bash
uv pip install --python .venv/bin/python './runbridge_node-0.5.0-py3-none-any.whl[visual]' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv pip check --python .venv/bin/python
.venv/bin/runbridge-node run --config .runbridge/node.json --chrome-config .runbridge/chrome.json
```

扩展接受 Browscreen >=0.3.1,<0.4.0 的正式版本；导入失败、缺失或范围不符时保留基础执行，画面支持按真实上报判断。升级时使用发布者交付的版本／约束；源码锁文件维护属于开发流程。

## 3. 查询并交付

使用有效且覆盖资源的许可：

```bash
.venv/bin/runbridge-node inspect node_example --access-file .runbridge/chrome-access.json
```

替换真实节点 ID 和访问文件。预期 visual.supported=true；没有该许可的 ACTIVE 会话时 streams=[] 是正常状态。ONLINE、supported 或路径存在都不代表已经产生有效帧。

将许可和资源信息交给调用方，让其按 Hub 项目指南建立业务会话并订阅。同一会话的画面使用创建它的同一许可；其他许可不能查看。多页时由调用方明确选择目标，选择画面来源不会缩小整个浏览器实例授权。

## 4. 采集结束与排查

会话结束会停止采集和上传；订阅者单独退出不结束业务执行。Node 清理只处理自身采集进程和临时目录，已有 Chrome 及 Profile 保留。

中文显示方框时按[部署指南中的字体步骤](../deployment/部署与运行.md)在浏览器所属用户下补齐字库，刷新缓存并由所有者重启浏览器、重新确认端点。STALE／ERROR 或 cleanup=UNKNOWN 按[Node 排障](../deployment/运行与排障.md)处理，不能将旧图当作实时结果。
