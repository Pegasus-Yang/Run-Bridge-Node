# Node 状态检查与许可管理

[文档导航](../README.md) · [首次部署](../deployment/部署与运行.md) · [配置参数](../reference/部署配置与凭据.md)

本文供**已完成首次部署**的 Node 所有者日常使用。第一次安装请从部署指南第 1 节开始；它包含登记文件接收、自动生成身份、浏览器启动和交接的完整顺序。

以下命令都在 Node 设备执行。前提是 `.runbridge/node.json` 已登记成功，Node 服务在另一个终端常驻运行。

## 1. 用已有访问文件检查状态

打开新终端：

```bash
cd ~/runbridge-node
rb_node_id=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/node.json").read_text())["node_id"])')
.venv/bin/runbridge-node inspect "$rb_node_id" --access-file .runbridge/access.json --output json
```

`rb_node_id` 从本设备身份文件读取，不是要你填写的示例 ID。`access.json` 是之前签发的有效访问文件；若你的文件名不同，改成其实际路径。没有许可时先执行下一节，再查询。

检查 `connection_status=ONLINE`、`capabilities_stale=false`，以及所需资源的 `readiness=READY`／`occupancy=FREE`。BUSY 表示资源已有任务，不要另起 Node 争抢。同一许可的 ACTIVE 会话才会出现在其可见画面列表中。

## 2. 为一个调用方签发许可

受管理资源使用 `chromium`：

```bash
.venv/bin/runbridge-node grant --config .runbridge/node.json --resource-id chromium --expires-in 3600 --output .runbridge/access-2.json
```

已有 Chrome 把资源 ID 改为 `chrome`；自定义 ID 则填 YAML 浏览器设置中的 `resource_id`。`3600` 是一小时，`access-2.json` 是本次新文件名，便于保留原有许可。文件已存在时改用另一个未占用的名字；命令不会覆盖，也不会因为这个错误签发一份未保存的新许可。

命令用 `node.json` 证明所有者身份，向 Hub 申请独立许可，再写出访问 JSON。不同调用方分别签发，便于单独撤销。没有指定 `--resource-id` 的许可范围不限于某一个资源；日常交付时明确限制资源和期限。

交给调用方的是新生成的访问文件，以及实际资源 ID、模式和期限；已有 Chrome 还要提供已打开页面的精确 URL。文件格式和完整交接模板见[部署第 7 节](../deployment/部署与运行.md#7-检查状态并向调用方交付访问文件)。不要交付登记令牌或 Node 身份。

## 3. 查看到期时间和许可 ID

只显示管理需要的字段，不显示令牌：

```bash
.venv/bin/python - <<'PYCODE'
import json
from pathlib import Path

access = json.loads(Path(".runbridge/access-2.json").read_text(encoding="utf-8"))
for field in ("hub_url", "node_id", "grant_id", "expires_at"):
    print(f"{field}: {access.get(field)}")
PYCODE
```

文件名换成你要管理的那份。`expires_at=null` 表示签发时未设置期限，仍可撤销；本地改时间不能更改 Hub 上的许可。

## 4. 撤销一份许可

先确认文件对应的调用方。下面读取 `access-2.json` 的真实许可 ID 并撤销：

```bash
rb_grant_id=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/access-2.json").read_text())["grant_id"])')
.venv/bin/runbridge-node revoke "$rb_grant_id" --config .runbridge/node.json
```

应输出“许可已撤销”。撤销会拒绝后续认证，并触发该许可的活动会话关闭；不会注销设备，也不会回滚已经发生的网页操作。继续核对会话清理，不能以发出撤销请求代替确认。

到期后的“续期”是重新签发新文件并交付调用方，旧文件保持失效。新许可不能接管旧许可创建的会话；新任务申请新会话。

## 5. 查看或关闭本许可的会话

从调用方本次执行输出中取得真实 `session_id`，替换下面的 `session_example`；该 ID 不是访问 JSON 里的节点或许可 ID：

```bash
.venv/bin/runbridge-node session get session_example --access-file .runbridge/access.json
```

需要主动结束该任务时才执行：

```bash
.venv/bin/runbridge-node session close session_example --access-file .runbridge/access.json
```

必须选**创建该会话的同一份访问文件**，即使另一份许可也属于同一节点，也不能用它接管会话。正常结束检查 `cleanup=COMPLETE`；PENDING／UNKNOWN 按[排障](../deployment/运行与排障.md)核查。

## 6. 停止与重启

先让调用方释放活动任务，再在原 Node 服务终端按 Ctrl+C。重启时执行 `.venv/bin/runbridge-node run --settings node.yaml`，保留 `node.json`，不重复创建身份。Chrome 模式还要确认原浏览器仍在、授权端点未变化。

一次只运行一个相同身份的常驻 Node。普通断线无需删除配置重新登记；READY／ACTIVE 和 cleanup 也不代表网页业务已经通过验证。

同一机器运行多个不同身份的实例，按[多 Node 部署](../deployment/同机运行多个Node.md)分别保存设置和身份；不能复制同一身份当成另一个实例。
