# Node 快速开始

简体中文 · [English](快速开始.en.md)

从 GitHub 源码直接体验，请先按[项目首页](../../README.md#快速开始)安装。本文说明已有 wheel 的独立目录部署，后续配置、验证和交付流程相同。

在 **Node 设备**上完成安装、登记、上线、设备标识交付及可选会话诊断。默认使用每次新建浏览器的 managed 模式；适用于 **0.8.2**。Hub 应已由部署者启动，本文不部署 Hub。

## 开始前

向 Hub 部署者或发布负责人取得以下材料：

| 材料 | 如何使用 |
| --- | --- |
| Hub 基址 | 如 `http://192.168.50.10:8787`，换成收到的实际地址；不能带 `/mcp`、`/v2` 或 `/health` |
| 真实 `enrollment.token` 文件 | Hub 的 `generate-token` 生成且 Hub 当前读取的同一份 UTF-8 单行文本，不要自行生成替代值 |
| `runbridge_node-0.8.2-py3-none-any.whl` | 本项目发布包；与登记附件一起保存到 `~/Downloads/` |

需要 Python **3.14.x**、全局 uv 和可运行 Chromium 的系统环境。基础准备参考 [Python](https://www.python.org/downloads/)、[uv](https://docs.astral.sh/uv/getting-started/installation/)、[Playwright 系统要求](https://playwright.dev/python/docs/intro#system-requirements)，本项目不负责安装这些基础工具。

先从 Node 设备访问实际 Hub，例如：

```bash
curl --fail http://192.168.50.10:8787/health
```

替换示例地址，返回应为 `{"status":"ok","protocol_version":2}`。远程 Hub 不能写成 `127.0.0.1`；那表示 Node 自己。

## 安装项目并保存登记附件

在全新部署目录执行：

```bash
mkdir -p ~/runbridge-node
cd ~/runbridge-node
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_node-0.8.2-py3-none-any.whl[playwright]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
umask 077
mkdir -p .runbridge
cp -n ~/Downloads/enrollment.token .runbridge/enrollment.token
chmod 600 .runbridge/enrollment.token
```

`[playwright]` 会把 Python Playwright **1.63.0** 安装在同一 `.venv`，其他 Python 环境中的包不会自动共用。登记文件直接保存原内容，不加引号、JSON、`Bearer ` 或 `token=`。已有部署保留原身份和附件，不覆盖另一个环境。

## 准备浏览器并创建 YAML

按 [Playwright 官方浏览器说明](https://playwright.dev/python/docs/browsers)，使用本部署 `.venv` 中的 Python Playwright 准备匹配 Chromium 及系统依赖。已经安装匹配版本时可以复用；安装与运行使用同一用户及缓存环境。无需单独安装 Node.js/npm，项目不会自动下载浏览器。

在部署目录创建 `node.yaml`，将第一行换成真实 Hub 基址：

```yaml
hub_url: http://192.168.50.10:8787
enrollment_token_file: .runbridge/enrollment.token
tools:
  playwright: {}
```

这份最小配置使用默认值：配置格式 2、本机名称、身份 `.runbridge/node.json`、资源 ID `chromium`、managed 模式、无头浏览器、启动超时 20000 毫秒。相对路径以 **node.yaml 所在目录**为准，不展开 `~` 或 `$HOME`。

如已有自选浏览器或需要复用 Chrome 登录，请按[参数详解](../reference/参数详解.md)选择 `channel`、`executable_path` 或 borrowed 模式，不要同时混合两种模式的字段。完整[注释样例](../reference/examples/Node启动配置.yaml)列出了配置说明。

## 启动并检查上线

```bash
.venv/bin/runbridge-node run --settings node.yaml
```

首次自动生成稳定身份、登记、探测浏览器并上线。保留前台终端，无需先执行register。把日志中的node_id、资源IDchromium及managed模式交给Hub部署者或调用方。通过Hub独立只读总览检查ONLINE、非stale与资源READY/FREE；ONLINE只表示连接存在。

## 使用权由 Hub 分配

Node 0.8.2配套Hub 0.9.3。grant/revoke命令已移除，设备只负责注册、能力和执行。调用方拿到Hub独立申请凭据，查询资源池并领取整个Node，保存Hub返回的五字段access.json，再通过HTTP/MCP使用。Node进程不接收Hub申请凭据。

默认租期3600秒、空闲回收600秒、最大租期默认86400秒；后两项由Hub配置，申请时可指定合法租期。inspect是可选的调用方诊断，不是Node申请授权的步骤；首次上线不需要访问文件。

## 验证一次真实浏览器会话

本节是可选维护诊断。先按Hub《调用方对接与使用》使用Hub认证领取当前Node，保存真实access.json到.runbridge/access.json；同一份租约不能同时转交给另一任务。保持Node运行，在第二个终端执行：

```bash
.venv/bin/runbridge-node session create --access-file .runbridge/access.json > .runbridge/session.json
```

成功后，将返回 JSON 中的真实会话 ID 读入变量，再查询与释放：

```bash
rb_session_id=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/session.json").read_text())["session_id"])')
.venv/bin/runbridge-node session get "$rb_session_id" --access-file .runbridge/access.json
.venv/bin/runbridge-node session close "$rb_session_id" --access-file .runbridge/access.json
```

创建命令失败时先排障，不继续解析输出。成功查询应为 `READY` 或 `ACTIVE`，`objects.pages` 包含实际创建的 `about:blank` 页面；关闭返回 `cleanup=COMPLETE`，再次 `inspect` 应恢复 READY/FREE。这一步会真实启动和回收 Chromium，并验证 Hub 会话路由。默认无头运行，不弹出窗口是正常现象。

本例使用默认工具 `playwright`、资源 `chromium` 和 300 秒租期；无需重复传这些参数。`session.json` 只保存本次返回结果，不是新的启动配置。需要修改资源时见[会话参数](../reference/参数详解.md#会话命令)。

## 交付与日常重启

设备维护者交付node_id、资源ID、模式和实际版本；调用方从Hub取得自己的访问文件。借用Chrome另提供原页面的精确URL，不交付node.json、登记文件、本地端点或Profile。会话诊断完成后关闭会话还需按Hub手册释放该Node租约并确认RELEASED，不能只看资源FREE。

停止前先让调用方释放会话，再在原 Node 终端 Ctrl+C。重启只需原来的 `run --settings node.yaml`。已有身份时可以移除 YAML 的 `enrollment_token_file` 字段；保留则每次启动幂等确认登记。不要删除 `node.json` 来处理网络问题。

## 任务结束和清理未知

调用方整批结束、取消或失败时，用原access_token请求DELETE /v1/grants/{grant_id}。RELEASING表示仍在清理；RELEASED才表示交还；QUARANTINED仍阻止新领取。原令牌失效后只能查询原租约和幂等释放，不能换令牌接管旧会话。具体操作与离线核查见Hub手册。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| Hub health 不通 | 核对收到的实际基址、监听地址、网络和代理；此时先联系 Hub 部署者，不需要重建身份 |
| 登记 401 | 使用 Hub 当前读取的原登记附件，检查单行文本格式和两端版本 |
| 提示配置无效 | YAML 用空格，顶层为对象，字段用 snake_case；核对[参数详解](../reference/参数详解.md) |
| ONLINE 但资源 UNAVAILABLE | 在同一用户、同一 `.venv` 和缓存环境检查 Chromium、系统库及桌面权限；先解决浏览器探测失败 |
| 无头运行看不到窗口 | 默认 `headless=true`；需要观察可使用画面流，或在有桌面的设备配置 `launch_options: {headless: false}` |
| grant/revoke提示命令无效 | 已移除，调用方改从Hub申请及释放Node；不要向Node身份文件加入Hub申请令牌 |
| 资源 BUSY | 当前有会话，查询自己刚创建的会话并正常释放，不重复创建来解除占用 |
| cleanup UNKNOWN | 保留活动记录，按[排障手册](../deployment/运行与排障.md)确认本次进程归属，不批量终止 Chrome |
| 重启后另一个 Node 掉线 | 检查两个进程是否共用 `identity_file`；每个实例必须有独立 YAML 和身份 |
| 修改 Hub 地址后提示身份属于其他 Hub | 已保存身份中的基址必须一致；先确认是在迁移现有 Hub 还是连接新 Hub，不能仅改 YAML 后强行使用旧身份 |
| borrowed 连接失败或钥匙链提示 | 使用[Chrome 复用指南](Chrome复用快速开始.md)及[凭据说明](../deployment/浏览器凭据与测试数据.md)，由所有者确认原实例配置 |

长期部署、文件格式与交付细节见[完整部署手册](../deployment/部署与运行.md)；升级与更多故障见[运行与排障](../deployment/运行与排障.md)。
