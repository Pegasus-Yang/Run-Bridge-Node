# Node page capture

[简体中文](浏览器画面采集.md) · English

In Node **0.8.1**, managed capture uses the same Page in the Python worker. It does not require `[visual]`; action `page_id` equals visual `target_id`. Normal startup probes screenshot support. Clients use visual paths returned by Hub queries, so device owners need not collect stream addresses.

Borrowed mode supports the optional Browscreen extension. Stop this instance and install the same wheel with `[playwright,visual]`, following the [deployment command](../deployment/部署与运行.en.md) with the extra changed. The accepted range is `browscreen>=0.3.1,<0.4.0`; actual probing must pass before support is advertised. Restart with the same YAML, without another browser service.

Capture is independent of the action queue. Clients explicitly select among multiple pages; closing a selected page does not silently select another logged-in page. Internal CDP targets map to session Page references. Endpoints stay local; authorization still covers the entire instance.

Frames are observations. Device administrators manage fonts, desktop sessions, window state, and system libraries. LIVE or a screenshot does not prove a business submission succeeded. Remove old images after session end; unknown cleanup quarantines resources. Client behavior is described in the [Hub streaming guide](https://github.com/Pegasus-Yang/Run-Bridge-Hub/blob/main/doc/user-guide/浏览器画面流接入.en.md).
