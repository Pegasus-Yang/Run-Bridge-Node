# Node deployment and operation

[简体中文](部署与运行.md) · English

Applies to **Node 0.8.1 / Hub 0.9.2**. Run commands on the **Node device**. Use the [README](../../README.en.md#quick-start) for source installation; this guide deploys a wheel into a separate directory. Use that installation's `.venv` and files consistently. Node initiates its connection to an existing Hub.

## 1. Obtain material and check the environment

Obtain the actual Hub base URL, its original `enrollment.token`, `runbridge_node-0.8.1-py3-none-any.whl`, the manuals and annotated YAML, and whether Hub enables MCP. The URL must be reachable from this device and have no `/mcp` or `/v2` suffix.

Enrollment is UTF-8 single-line text, 32–256 characters, with an optional final newline. Do not add JSON, quotes, `Bearer `, or `token=` or generate a replacement token. Save the received attachment and wheel under `~/Downloads/`. A format illustration, never a real credential:

```text
EXAMPLE_ONLY_ENROLLMENT_TOKEN_DO_NOT_USE_00000000000000000000000
```

Prepare Python **3.14.x**, global [uv](https://docs.astral.sh/uv/getting-started/installation/), and browser system libraries, permissions, and fonts. See [Python](https://www.python.org/downloads/) and [Playwright requirements](https://playwright.dev/python/docs/intro#system-requirements). Python Playwright includes its driver, so no separate Node.js/npm deployment is required.

```bash
curl --fail http://192.168.50.10:8787/health
```

Replace this address. Expect `{"status":"ok","protocol_version":2}`. Health does not return package versions; confirm Node 0.8.1 and Hub 0.9.2 with the deployers. A remote Hub URL cannot use Node's own `127.0.0.1`.

## 2. Install the package and Python tool

```bash
mkdir -p ~/runbridge-node
cd ~/runbridge-node
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_node-0.8.1-py3-none-any.whl[playwright]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
umask 077
mkdir -p .runbridge
chmod 700 .runbridge
cp -n ~/Downloads/enrollment.token .runbridge/enrollment.token
chmod 600 .runbridge/enrollment.token
.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-node"))'
```

Expect version `0.8.1`. `[playwright]` installs Python Playwright **1.63.0** in the same environment. Other environments are not searched automatically. `cp -n` preserves an existing file; existing deployments reuse their own original identity and enrollment file.

## 3. Prepare the browser

Use this `.venv` to prepare matching Chromium and system dependencies following the [Playwright browser guide](https://playwright.dev/python/docs/browsers). Node does not download browsers or install system libraries on startup. Use the same browser cache during installation and execution; defaults follow `PLAYWRIGHT_BROWSERS_PATH` or Playwright's cache. `browser_cache_directory` can select another cache.

The owner validates compatibility of a custom `channel` or `executable_path`. Managed sessions use dedicated temporary profiles and explicit local-storage startup arguments, without requiring keychain approval. See [credentials and test data](浏览器凭据与测试数据.en.md).

Borrowed mode also needs Python Playwright. Prepare the explicitly authorized existing instance using the [Chrome reuse guide](../user-guide/Chrome复用快速开始.en.md); Node does not start another browser for that mode.

## 4. Save YAML and connect

Create UTF-8 `node.yaml` in `~/runbridge-node`:

```yaml
hub_url: http://192.168.50.10:8787  # Replace with the actual Hub base URL.
enrollment_token_file: .runbridge/enrollment.token
tools:
  playwright: {}
```

Defaults are identity `.runbridge/node.json`, resource `chromium`, managed headless mode, and a `20000` ms launch timeout. Use spaces, not tabs. Relative local paths resolve from the **YAML directory**, without expanding `~` or `$HOME`. See [parameters](../reference/参数详解.en.md) and [annotated YAML](../reference/examples/Node启动配置.en.yaml). For borrowed mode, replace the tool section with its guide's version and remove managed launch/cache fields.

```bash
chmod 600 node.yaml
.venv/bin/runbridge-node run --settings node.yaml
```

First startup creates private identity, enrolls with Hub, probes the actual browser, and establishes the outgoing connection and heartbeats. Keep the foreground terminal running. No separate `register`, BrowserServer port, browser PID handoff, or runtime preparation command is needed.

A failed network request preserves the generated identity; retry with the same YAML after fixing the network. After enrollment, omitting `enrollment_token_file` reconnects using identity; keeping it confirms enrollment idempotently. Changing YAML `name` does not rename an existing identity.

## 5. Verify and hand off device identifiers

Give the logged Node ID, resource ID, and mode to the Hub deployer. To read the nonsecret ID locally:

```bash
.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/node.json").read_text())["node_id"])'
```

Use the actual path when `identity_file` differs. In Hub's dashboard check ONLINE, fresh capabilities, and resource READY/FREE. ONLINE alone is insufficient. Startup probing really creates and cleans up a dedicated browser. `node_token` authenticates device connections; Node need not claim itself.

## 6. Hub allocates client leases

Hub deployers privately give clients the base URL and separate `hub_token`. Clients query the pool, claim the entire Node, and save the returned five-field `access_config`, then execute through Hub. Node does not receive the Hub claim credential or maintain user accounts.

Defaults: Node lease 3600 seconds, maximum 86400, idle timeout 600; the last two are Hub settings. Closing a browser session does not return Node. Clients release it at batch completion, cancellation, or failure, and await confirmed cleanup. Unknown cleanup remains QUARANTINED.

Optional device-side `inspect` / `session` diagnostics use a lease already claimed by the client; they do not create ownership and are not required for enrollment. See the [quick-start diagnostic](../user-guide/快速开始.en.md#verify-a-real-browser-session). For borrowed Chrome, also hand off the exact authorized page URL and scope. Keep CDP endpoints, identity, enrollment files, and profiles on the device. Client execution is documented by the [Hub client guide](https://github.com/Pegasus-Yang/Run-Bridge-Hub/blob/main/doc/user-guide/调用方对接与使用.en.md).

## 7. Shutdown, restart, and long-term operation

Have clients close sessions and verify `cleanup=COMPLETE`, then use Ctrl+C or SIGTERM. Managed cleans up this session's browser and profile. Borrowed disconnects RunBridge, retaining original Chrome, pages, cookies, localStorage, and page changes already made.

Restart with the same YAML and identity. Do not run two processes with the same identity. A process manager should use absolute CLI/YAML paths and preserve the user, browser cache, desktop, and proxy environment. Device administrators manage fonts and system dependencies.

See [multiple Nodes](同机运行多个Node.en.md) for concurrency and [operations](运行与排障.en.md) for upgrades and failures.
