# Node 运行与排障

[文档导航](../README.md) · [部署与运行](部署与运行.md) · [配置参考](../reference/部署配置与凭据.md)

适用于 Node 0.5.0。先确认远程 Hub 地址和本机身份，再检查所选浏览器资源；服务端配置问题交由 Hub 部署者处理。

## 网络、身份与路径

| 现象 | Node 所有者检查 |
| --- | --- |
| 远端 health 不通 | Hub 实际基址、路由、防火墙、HTTP／WS 代理与证书；联系服务端部署者 |
| register 失败但 node.json 已生成 | 保留文件以同一命令重试，以登记响应成功为准 |
| 身份被拒绝或连接被替换 | 所属 Hub 是否正确、是否有同身份第二个常驻进程 |
| 找不到配置／运行时／Node.js | 服务工作目录、绝对路径和非交互 PATH；JSON 不展开 shell 变量 |
| 只有 ONLINE 没有资源 | 是否提供了一种浏览器配置，并实际上报 READY/FREE |
| grant 输出文件已存在 | 复用有效许可或选新文件名，命令不会覆盖 |

配置字段、纯文本登记文件和私有权限按配置参考处理。不要删除身份、重建节点或关闭证书校验来修复暂时网络故障。

## 已有 Chrome

| 现象 | 检查 |
| --- | --- |
| 配置无效 | BROWSER_INSTANCE、固定回环浏览器级 ws 地址和实际端口／ID |
| 资源 UNAVAILABLE | 所有者浏览器是否仍运行、端点是否变化、本机依赖是否完整 |
| 重启浏览器后不能恢复 | 重新确认新的浏览器 ID，更新配置并正常重启 Node |
| 找不到原页面 | 调用方使用已有 context/pages，并明确唯一目标；不自动创建新登录 |
| 关闭命令被拒绝 | 借用模式保护整个浏览器；释放本次 SDK／会话连接即可 |

Node 只有借用连接与自身采集的清理权，不拥有原浏览器进程或 Profile。不要清理全部 Chrome 进程。

## 受管理 Chromium

| 现象 | 检查 |
| --- | --- |
| prepare-playwright 拒绝目录 | 已有不同锁文件，选择独立新目录，不删共享缓存 |
| PLAYWRIGHT_START_FAILED／资源不可用 | Node.js、npm、私有运行时、浏览器库、图形环境和本地启动选项 |
| timeout 调大仍超时 | 启动参数为毫秒，Node 外层等待 helper 就绪最多 30 秒 |
| 版本不匹配 | 调用方 SDK 与 npm Playwright 主次版本；已验收版本 1.63.0 |
| cleanup UNKNOWN | 核对运行时目录内 cleanup-unknown-node_id.json 记录的本次自建 PID／进程组和临时目录 |

未知清理标记只能在所有者确认对应自建进程已退出、专用临时目录已处理后移除并重启。持久输出目录及无关浏览器不属于此次清理。

## 许可、会话与画面

401 核对访问文件是否过期／撤销；更改本地 JSON 的期限不会更改远端授权。会话查询和释放使用创建它的同一许可。RESOURCE_BUSY 或 cleanup 未确认时不重复抢占。

已有 Chrome 画面需本机 visual extra 和该许可的 ACTIVE 会话；没有活动会话时 streams=[] 正常。MCP 受管理画面由服务端提供，普通 SDK 受管理会话无独立流。扩展失败与采集错误不自动说明网页业务失败。

中文方框按[部署指南的字体步骤](部署与运行.md)处理，在浏览器所属用户下刷新缓存并由所有者重启浏览器，随后更新 Chrome 授权端点。DOM 中文正确或 fc-list 非空不能代替实际截图核验。

## 停止与反馈

先释放会话，再正常停止 Node。已有 Chrome 保留，受管理实例要确认回收。记录当前版本、模式、公开错误、节点／会话标识和清理状态；不回显令牌或本机私有端点。

源码构建、测试和开发调用方样例见[开发与联调](../development/本地开发与联调.md)。
