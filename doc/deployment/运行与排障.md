# Node 运行、排障与升级

适用于 0.7.0。先检查当前 YAML、身份路径、程序绝对路径与使用的 `.venv`；不要修改原有其他部署环境。

| 现象 | 检查和处理 |
| --- | --- |
| 首次登记失败 | Hub 可达、真实单行 enrollment.token、权限和 Hub 版本；保留生成身份再用同配置重试 |
| 重启替换另一实例 | 两个进程使用了同一身份文件；每个实例使用独立 YAML/身份 |
| 缺少 Python Playwright | 当前虚拟环境需本包 [playwright]，其他 Python 环境已装不代表当前可用 |
| ONLINE 但资源 UNAVAILABLE | 同用户实际浏览器/缓存/系统依赖/桌面权限，启动探测必须成功；基础准备参考官方文档 |
| 旧配置被拒绝 | 改为 config_version: 2 与 tools.playwright，Python snake_case；旧顶层 chrome/playwright 和 npm 配置不兼容 |
| borrowed 端点失效 | Chrome 重启后浏览器 ID 改变；由所有者重新确认固定本机实例并更新配置 |
| cleanup UNKNOWN | 保留 state-node_ID 活动记录，检查其 PID、创建时间、短目录和 marker；不要按进程名批量杀 Chrome或删除其他 Profile |
| managed 画面不可用 | 检查会话 ACTIVE、Page 是否存在及 Node 截图；无需 [visual] |
| borrowed 画面不可用 | 该环境需兼容的 [visual] 扩展、固定实例和实际能力探测；不影响普通动作合同 |
| 中文截图方框 | Node 浏览器用户的字体问题，由设备管理员按系统官方说明准备，再核对真实图像 |
| 测试 Chrome 请求钥匙链 | managed 已显式保留本地存储参数；核对是否绕开 Node 直接启动 Chrome，或使用既有 borrowed 实例，按[凭据说明](浏览器凭据与测试数据.md)处理 |
| borrowed 点击后台页超时 | 确认使用当前包，输入前会激活明确指定的 Page；同 URL 多页应结合内容确认引用，避免操作错页 |

## 从 0.6.0 升级到 0.7.0

0.7.0 更新发布版本、用户入口、参数与验证文档；Node 工具执行协议及行为保持 0.6.0 的合同。正常停止目标实例并备份 YAML 和身份后，用该部署环境的 uv 安装新的 Node wheel，继续使用原 YAML、身份和浏览器环境。YAML 格式仍为 2，身份格式仍为 1；不重新登记身份或改写访问许可。

安装和升级不自动启动 Node，运行验证由操作者随后完成。源码/tag 更新不等于虚拟机已安装新版本，应在目标 `.venv` 查询实际安装元数据。

## 从 0.5.x 或更早版本升级

先由调用方释放活动会话并核对业务状态，正常停止本实例，备份 YAML 和长期身份。使用 uv 在该部署 `.venv` 安装新 Node wheel 的 `[playwright]` extra；需要 borrowed 画面时使用 `[playwright,visual]`。基础浏览器准备继续遵循 Playwright 官方说明；项目不会自动下载安装浏览器。

身份 JSON 的 config_version=1 保持原值，稳定节点 ID、令牌和访问许可可复用。新的启动 YAML 使用 config_version=2，浏览器设置改为 tools.playwright。删除 node_executable/runtime_directory/use_default_browser_cache、camelCase launch_options、旧 CLI --playwright-config/--chrome-config；自定义缓存改 browser_cache_directory，默认不配置则遵循官方环境。

不再执行 prepare-runtime 或部署单独 npm Playwright。旧 npm 目录和旧环境不会自动删除；确认旧服务不再运行后由所有者归档。borrowed 原 Chrome 不在升级中自动关闭或重启。当前发布两端统一使用 0.7.0，旧 `/v1` 控制连接会被明确拒绝。

启动后检查 ONLINE、非过期、READY/FREE，再交付调用方做一次业务操作并确认 COMPLETE。重启不恢复旧会话对象和操作；网络重连、租期与撤销不撤销已有副作用。
