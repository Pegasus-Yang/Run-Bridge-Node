# Node 运行、排障与升级

简体中文 · [English](运行与排障.en.md)

适用于Node 0.8.1 / Hub 0.9.2。先检查当前 YAML、身份路径、程序绝对路径与使用的 `.venv`；不要修改原有其他部署环境。

| 现象 | 检查和处理 |
| --- | --- |
| 首次登记失败 | Hub 可达、真实单行 enrollment.token、权限和 Hub 版本；保留生成身份再用同配置重试 |
| 重启替换另一实例 | 两个进程使用了同一身份文件；每个实例使用独立 YAML/身份 |
| 缺少 Python Playwright | 当前虚拟环境需本包 [playwright]，其他 Python 环境已装不代表当前可用 |
| ONLINE 但资源 UNAVAILABLE | 同用户实际浏览器/缓存/系统依赖/桌面权限，启动探测必须成功；基础准备参考官方文档 |
| 旧配置被拒绝 | 改为 config_version: 2 与 tools.playwright，Python snake_case；旧顶层 chrome/playwright 和 npm 配置不兼容 |
| borrowed 端点失效 | Chrome 重启后浏览器 ID 改变；由所有者重新确认固定本机实例并更新配置 |
| cleanup UNKNOWN | 保留 state-node_ID 活动记录，检查其 PID、创建时间、短目录和 marker；不要按进程名批量杀 Chrome或删除其他 Profile |
| managed 画面不可用 | 检查会话 ACTIVE、Page 是否存在及 Node 截图；无需 [visual] |
| borrowed 画面不可用 | 该环境需兼容的 [visual] 扩展、固定实例和实际能力探测；不影响普通动作合同 |
| 中文截图方框 | Node 浏览器用户的字体问题，由设备管理员按系统官方说明准备，再核对真实图像 |
| 测试 Chrome 请求钥匙链 | managed 已显式保留本地存储参数；核对是否绕开 Node 直接启动 Chrome，或使用既有 borrowed 实例，按[凭据说明](浏览器凭据与测试数据.md)处理 |
| borrowed 点击后台页超时 | 确认使用当前包，输入前会激活明确指定的 Page；同 URL 多页应结合内容确认引用，避免操作错页 |

## 从0.7.0升级到0.8.1

先让调用方结束任务、关闭浏览器并交还Node，正常停止本实例。备份原YAML、node.json及活动记录，在原部署.venv安装新wheel，保留原身份、配置格式2和浏览器环境：

```bash
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_node-0.8.1-py3-none-any.whl[playwright]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-node"))'
.venv/bin/runbridge-node run --settings node.yaml
```

版本应为0.8.1。安装不会自动启动服务，上面最后一条由操作者执行。Hub同步升级0.9.2并按其手册迁移schema5：旧grant全部失效，调用方从Hub重新领取，不重建Node身份。Node已移除grant/revoke；node_token仍认证控制、执行连接和上传。inspect/session是使用现有Hub租约的可选诊断，不是设备上线必需流程。

## 更早版本

0.5.x及更早的npm BrowserServer、prepare-runtime和原生SDK入口已退役。备份原设备身份，迁移到config_version=2与tools.playwright，使用Python Playwright及snake_case参数。删除旧node_executable/runtime_directory/use_default_browser_cache、camelCase启动字段和--playwright-config/--chrome-config；缓存使用browser_cache_directory。基础浏览器准备按Playwright官方说明执行，项目不会启动时下载浏览器。

稳定身份JSON格式仍为1。borrowed原Chrome不因升级自动关闭或重启，旧目录不自动删除；确认旧服务停止后由维护者归档。所有调用方访问许可需按Hub0.9.2重新领取。

## 清理未知与租约交接

Node离线、重启或worker异常不能证明浏览器已清理。保留state-node_ID记录，按原会话PID创建时间和专用目录核查，禁止按进程名批量杀Chrome。Hub会保留QUARANTINED并阻止新领取；即使Node重连并报告FREE，也不伪造原会话COMPLETE。

确认原范围清理后，将已核查活动记录归档到state目录之外保留证据，再允许Node重新探测。随后由Hub维护者停止Hub与相关Node，使用Hub的confirm-cleanup记录对应grant_id证据，保留原UNKNOWN，再恢复服务。普通Hub申请令牌没有强制接管能力。操作步骤、证据格式及备份要求见Hub《运行与排障》。

关闭浏览器会话不会自动释放Node；整批任务结束、取消或失败均由调用方单独释放。默认空闲600秒回收，状态轮询、心跳、画面和续租不能维持占用；真实动作及有界在途执行按Hub规则计时。已经发生的业务修改不因租约释放而撤销。
