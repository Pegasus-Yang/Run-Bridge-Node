# Node operations, troubleshooting, and upgrades

[简体中文](运行与排障.md) · English

Applies to **Node 0.8.2 / Hub 0.9.3**. Check this instance's YAML, identity, absolute program path, and `.venv` first.

| Symptom | Check and action |
| --- | --- |
| Initial enrollment fails | Hub reachability, original single-line token, permissions, and versions; retain identity and retry the same configuration |
| Restart replaces another instance | Use distinct identity files for each process |
| Missing Python Playwright | Install this package's `[playwright]` in the actual `.venv` |
| ONLINE but UNAVAILABLE | Browser, cache, system libraries, and desktop permissions under the same user; real probing must pass |
| Old settings rejected | Use YAML format 2 and `tools.playwright`, snake_case options; old top-level and npm settings are retired |
| Borrowed endpoint expired | Chrome restart changes its browser ID; owner reconfirms the exact local instance |
| UNKNOWN cleanup | Preserve `state-node_ID` records; check PID creation time, short directory, and marker |
| Managed frames unavailable | Active session, actual Page, and screenshot capability; `[visual]` is not needed |
| Borrowed frames unavailable | Compatible optional `[visual]`, fixed instance, and actual capability probe |
| Missing Chinese glyphs in screenshots | Device administrator prepares fonts for the browser user, then verifies an actual image |
| Keychain request | Check direct Chrome launches or borrowed startup; see [credential handling](浏览器凭据与测试数据.en.md) |
| Borrowed background-page input times out | Current package activates the explicitly chosen Page for input; disambiguate same-URL pages by content |

## Upgrade from 0.8.1 to 0.8.2

This patch changes public package presentation, distribution selection, and release checks. Browser execution, YAML format 2, identity format 1, resource and access contracts are unchanged. Finish tasks, return Node, stop this instance, install 0.8.2 in its original `.venv`, and restart with the original YAML. Preserve identity, enrollment material, and browser environment. Hub 0.9.2 remains compatible; Hub 0.9.3 is the current paired package.

## Upgrade from 0.7.0 to 0.8.2

Have clients finish tasks, close sessions, and return Node. Stop this instance, back up YAML, identity and activity records, and install into its original environment. Retain identity, YAML format 2, and browser setup:

```bash
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_node-0.8.2-py3-none-any.whl[playwright]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-node"))'
.venv/bin/runbridge-node run --settings node.yaml
```

Expect `0.8.2`. Installation does not start service; the final command is an explicit operator action. Upgrade Hub to 0.9.3 following its [operations guide](https://github.com/Pegasus-Yang/Run-Bridge-Hub/blob/main/doc/deployment/运行与排障.en.md), including schema 5 migration where applicable. Old grants become invalid; clients claim through Hub again. Device identity need not be recreated.

Node `grant` / `revoke` are removed. `node_token` still authenticates device control, execution, and upload connections. `inspect` / `session` are optional diagnostics using an existing Hub lease.

## Earlier versions

The 0.5.x-era npm BrowserServer, `prepare-runtime`, and native SDK entry are retired. Back up identity and move to YAML `config_version: 2`, `tools.playwright`, Python Playwright, and snake_case fields.

Remove old `node_executable`, `runtime_directory`, `use_default_browser_cache`, camelCase launch fields, `--playwright-config`, and `--chrome-config`. Use `browser_cache_directory` for a custom cache. Prepare browsers according to Playwright documentation; startup does not download them.

Stable identity JSON remains format 1. Upgrading does not close or restart the original borrowed Chrome or automatically delete old directories. Archive old data only after confirming the old service stopped. Clients obtain new leases using the current Hub guide.

## Unknown cleanup and lease handoff

Node disconnect, restart, or worker failure does not prove browser cleanup. Keep `state-node_ID` records and verify the original session's processes by PID creation time and dedicated paths. Do not terminate unrelated Chrome processes or remove other profiles.

Hub retains QUARANTINED and blocks claims even if Node reconnects reporting FREE. After verifying the original scope is cleaned, archive reviewed activity records outside the state directory, preserving evidence, and let Node probe again.

The Hub maintainer then stops Hub and related Nodes and uses `confirm-cleanup` to record evidence for the original `grant_id`, preserving original UNKNOWN. Follow the Hub operations guide for evidence format and backups. A shared Hub claim token cannot force takeover.

Clients separately release Node at batch completion, cancellation, or failure. Default idle reclaim is 600 seconds; status polling, heartbeats, frames, and renewals do not maintain occupancy. Actual actions and bounded in-flight execution follow Hub's activity rules. Resource release does not undo business changes already made.
