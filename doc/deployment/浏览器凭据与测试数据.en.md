# Browser credentials and test data

[简体中文](浏览器凭据与测试数据.md) · English

Applies to **Node 0.8.2**. Enrollment, identity, and access credentials use [private files](../reference/部署配置与凭据.en.md), not macOS Keychain, GNOME Keyring, or another system credential store.

## Managed browser storage

Managed mode creates a temporary profile per session and removes it on release. It neither retains previous login state nor imports personal Chrome passwords. Node appends `--password-store=basic` and `--use-mock-keychain` to select local basic storage and avoid system-keychain access by the test browser. These remain even when `ignore_default_args` filters SDK defaults; YAML cannot switch them back to system storage.

The [Playwright Chromium defaults](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/server/chromium/chromiumSwitches.ts) also include these options. Test scripts launching the Chrome executable directly must preserve them themselves. RunBridge does not require approval of keychain prompts.

## Test data belongs to the client or test script

The website URL, dedicated account, and business inputs can be kept in a private UTF-8 file, for example `.runbridge/test-data.json`:

```json
{
  "base_url": "https://test.example.com",
  "username": "test-user",
  "password": "REPLACE_WITH_DEDICATED_TEST_ACCOUNT_PASSWORD"
}
```

This is sample test-script data, **not Node configuration**. Node does not automatically read it or provide an account vault. Clients read their own data and send explicit inputs with `locator.fill` or MCP `browser_fill`. Keep secrets out of command histories, logs, public YAML, and commits. Use directory mode 700 and file mode 600, with private directories ignored by Git.

Browser cookies/localStorage live in the session profile and disappear after managed release. The public methods do not expose arbitrary `storage_state` import, persistent profiles, or arbitrary Node-local file reads.

## Borrowed Chrome

An already running browser keeps its original credential backend. Node cannot change its launch options, restart it, or unlock its store. The owner can prepare a dedicated test Chrome/profile with appropriate startup options. If an existing instance prompts for system credentials, end the RunBridge session and let the owner manage that browser; a Node setting cannot retroactively change it.

Basic storage does not have system-keychain encryption protection and is for controlled dedicated test data. Keep personal browser profiles separate. Disconnecting borrowed mode preserves original browser, pages, and login data; see [Chrome reuse](../user-guide/Chrome复用快速开始.en.md).
