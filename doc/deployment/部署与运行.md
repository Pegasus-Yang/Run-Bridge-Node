# RunBridge Node 部署与运行

[文档导航](../README.md) · [配置与参数查询](../reference/部署配置与凭据.md) · [运行与排障](运行与排障.md)

本文面向浏览器设备的所有者，带你安装 **Node 0.5.0**、向已经存在的远程 Hub 登记、准备浏览器，再向调用方交付访问文件。命令使用 macOS／Linux 的 Bash 或 Zsh。所有安装操作都在 **Node 设备**进行。

## 先看操作顺序

依次完成第 1～5 节，再按第 6 节进入一种浏览器指南；浏览器指南会让你返回第 7 节检查和交付。第 8～10 节按需查阅。Node 设备不用安装或启动 Hub。

| 名称 | 在这里表示什么 |
| --- | --- |
| Hub 地址／基址 | Hub 部署者提供的远程服务地址，例如 `http://192.168.50.10:8787` |
| 登记文件 `enrollment.token` | Hub 部署者在服务器生成并交给你的单行文本，用于首次登记 |
| 身份文件 `node.json` | 首次启动自动生成，本设备今后连接 Hub 的长期身份 |
| 浏览器配置 | `node.yaml` 中所选模式的 `chrome` 或 `playwright` 设置 |
| 访问文件 `access.json` | 你登记后向 Hub 申请、交给调用方使用的独立许可；与登记文件不同 |

文中的地址、账号名和演示 ID 都不是现成的部署数据。`127.0.0.1` 只指当前设备自身：连接远程 Hub 使用其实际地址，本机 Chrome 的调试连接才使用回环地址。

## 1. 先取得完整的交接材料

安装前向 Hub 部署者或本次发布负责人确认：

| 材料 | 应拿到什么 | 提供者 |
| --- | --- | --- |
| Hub 地址 | 一条可从本设备访问的 HTTP(S) 基址，包含实际端口；不要在基址末尾加 `/health` 或 `/mcp` | Hub 部署者 |
| 登记文件 | 真实的 `enrollment.token` 附件；也可先取得其完整单行原文 | Hub 部署者 |
| Node 安装包 | `runbridge_node-0.5.0-py3-none-any.whl` | 发布负责人 |
| Node 文档包 | 本手册及 Chrome／受管理 Chromium 指南；wheel 本身不包含这些手册 | 发布负责人 |
| MCP 信息，若需要 | 远程 Hub 是否已启用 MCP，以及实际入口 | Hub 部署者 |

**登记文件从哪里来？**Hub 部署者运行自己项目手册中的 `generate-token`，生成服务器上的 `.runbridge/enrollment.token`，并让 Hub 启动时读取它。你收到的必须是那个文件的相同内容。Node 不需要、也不能另外随机生成一个值来与之配对。

文件格式为 UTF-8 纯文本，正文一行，末尾允许有换行。下面只是格式示意，不能用于实际登记：

```text
EXAMPLE_ONLY_ENROLLMENT_TOKEN_DO_NOT_USE_00000000000000000000000
```

不要添加 JSON、引号、`Bearer ` 或 `token=`。不要把说明文字一起复制进去，也不要保存成 `enrollment.token.txt`。Hub 生成的通常是 64 个字符；服务器接受 32～256 个字符的真实令牌。

收到文件附件时，先保存到本设备的 `~/Downloads/enrollment.token`；Node wheel 也先放在 `~/Downloads/`。没有下载目录可先运行 `mkdir -p ~/Downloads`。若只有令牌文字，第 4 节提供保存方法，不需要自行猜文件写法。

先检查远程 Hub 能否访问；下面地址要换成收到的真实地址：

```bash
curl --fail http://192.168.50.10:8787/health
```

应返回：

```json
{"status":"ok","protocol_version":1}
```

这条检查不使用令牌。设备没有 curl 但有浏览器时，也可直接在本设备浏览器打开同一个 `/health` 地址，看到上述 JSON 即可。连接拒绝或超时时先联系 Hub 部署者检查服务地址、防火墙和路由；此时不要修改凭据或重新建身份。检查通过再继续。

## 2. 准备全局 uv 和 Node 部署目录

在 Node 设备终端检查：

```bash
uv --version
```

部署前应已准备标准 CPython **3.14.x** 和可在服务环境中使用的全局 uv。uv 的安装、升级和 PATH 配置请参考 [uv 官方说明](https://docs.astral.sh/uv/getting-started/installation/)，Python 的获取方式参考 [Python 官网](https://www.python.org/downloads/)。已有满足要求的工具直接复用。

本手册只说明本项目的虚拟环境、程序包、配置和运行；不负责 Homebrew、uv 或操作系统环境的安装。命令找不到时先按工具官方说明处理环境，再继续。

创建独立目录：

```bash
mkdir -p ~/runbridge-node
cd ~/runbridge-node
pwd
```

`~` 表示当前账号的主目录。以后每个新终端先执行 `cd ~/runbridge-node`；后文命令行相对路径从这里计算，YAML 内相对路径则从文件所在目录计算。Hub 和 Node 即使由同一个人管理，也分别使用自己的目录和 Python 环境。

## 3. 安装 Node 程序

复制安装包，确认实际文件名：

```bash
cd ~/runbridge-node
cp -n ~/Downloads/runbridge_node-0.5.0-py3-none-any.whl ./
ls -l runbridge_node-0.5.0-py3-none-any.whl
uv venv --python 3.14 --no-python-downloads .venv
.venv/bin/python --version
```

uv 使用已准备的标准 CPython 3.14.x 创建 `.venv/`；找不到该版本时先按前置要求准备 Python，这条命令不会自动下载。已有有效环境时跳过 `uv venv`，其余命令继续使用原环境。`.whl` 是程序安装包，不要解压或用文本编辑器新建一个同名文件。

**通常先用基础安装**，它同时支持受管理 Chromium 和不采集持续画面的已有 Chrome：

```bash
uv pip install --python .venv/bin/python ./runbridge_node-0.5.0-py3-none-any.whl -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

如果已确定要采集已有 Chrome 的持续画面，则改用下面这一条，不需要两条都执行：

```bash
uv pip install --python .venv/bin/python './runbridge_node-0.5.0-py3-none-any.whl[visual]' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

`[visual]` 是可选扩展，安装 Browscreen 正式版 `>=0.3.1,<0.4.0`；引号要保留。它不是受管理 MCP 画面的前置条件，后续也可以补装。

如果发布负责人交付了同版 `deploy-constraints.txt`，将它复制到部署目录，并在所选安装命令末尾增加 `--constraint ./deploy-constraints.txt`。没有收到时跳过；它是依赖约束，不是 Node 配置。

检查安装：

```bash
.venv/bin/runbridge-node --help
uv pip check --python .venv/bin/python
```

应能看到 `register`、`run`、`grant`、`inspect` 等子命令，且依赖检查通过。所有命令已明确选中本目录的环境，不用另行激活，也不要求存在单独的 `pip` 命令。

## 4. 把登记文件放到正确位置

在 Node 部署目录建立私有目录：

```bash
cd ~/runbridge-node
umask 077
mkdir -p .runbridge
chmod 700 .runbridge
```

`.runbridge` 以点开头，是隐藏目录；`.venv` 存放程序环境，`.runbridge` 存放本次部署的数据和配置，两者不同。

### 已收到文件附件

假定已保存到 `~/Downloads/enrollment.token`：

```bash
cp -n ~/Downloads/enrollment.token .runbridge/enrollment.token
chmod 600 .runbridge/enrollment.token
ls -l .runbridge/enrollment.token
```

`cp -n` 不覆盖已有文件。如果目标已存在，请先确认它是否就是这个 Hub 的原登记文件，不要直接覆盖。权限应为 `-rw-------`；命令不需要打印令牌内容。

### 只有一行令牌文字

跳过上面的复制方式，在 Node 部署目录运行下面整段命令。出现提示后再粘贴 **Hub 部署者提供的真实原文**并按回车；输入时不显示内容，正常情况下不会进入 shell 历史：

```bash
.venv/bin/python - <<'PYCODE'
import os
from getpass import getpass

token = getpass("粘贴 Hub 提供的完整登记令牌（不显示）：").strip()
if not 32 <= len(token) <= 256 or "\n" in token or "\r" in token:
    raise ValueError("请粘贴 32～256 字符的单行真实令牌")
descriptor = os.open(".runbridge/enrollment.token", os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(descriptor, "w", encoding="utf-8") as output:
    output.write(token + "\n")
print("已保存 .runbridge/enrollment.token")
PYCODE
```

此方式也拒绝覆盖已有文件。完成后应有 `~/runbridge-node/.runbridge/enrollment.token`。这只是保存收到的内容，没有生成新的登记令牌。

## 5. 新建统一启动文件 node.yaml

在 `~/runbridge-node` 用文本编辑器新建 UTF-8 文件 `node.yaml`，填写实际 Hub 地址和设备名称：

```yaml
hub_url: http://192.168.50.10:8787
name: office-node
identity_file: .runbridge/node.json
enrollment_token_file: .runbridge/enrollment.token
```

```bash
chmod 600 node.yaml
```

| 字段 | 数据来源与含义 |
| --- | --- |
| `hub_url` | 第 1 节收到且已检查可达的远程基址 |
| `name` | 你给该 Node 起的名称；省略时使用机器名 |
| `identity_file` | 本程序首次启动时生成长期身份的位置；不需要提前创建 JSON |
| `enrollment_token_file` | 第 4 节保存的真实登记文本，只填写路径，不把令牌正文写进 YAML |

本节只保存设置，**还没有登记或启动**。第 6 节会在同一 YAML 中加入一种浏览器配置，再用 `run --settings node.yaml` 一次完成登记和上线，不需要先执行 `register`。

YAML 使用空格缩进，不用 Tab；字段之间用冒号，布尔值写 `true/false`。本地相对路径以 **node.yaml 所在目录**为基准，因此从其他工作目录启动也能定位相同身份和运行时。不要写 `~`、`$HOME` 或 shell 表达式。完整字段和旧 JSON 方式见[配置参考](../reference/部署配置与凭据.md)。

## 6. 选择一种浏览器模式并启动

| 你要做什么 | 选择哪篇指南 | 做完后得到什么 |
| --- | --- | --- |
| 每个任务创建新浏览器，不需要复用已有登录；或给 Agent 提供 MCP 资源 | [受管理 Chromium](../user-guide/Playwright快速开始.md) | 可用的 npm 运行时、完整 `node.yaml` 和一个常驻 Node |
| 操作某个明确授权的已有 Chrome 实例，保留其中页面和登录 | [Chrome 复用](../user-guide/Chrome复用快速开始.md) | 含实例授权的 `node.yaml` 和一个常驻 Node |

只走其中一条指南，完整执行到“返回部署指南”的位置。首次不确定且不需要已有登录时，可以选择受管理模式。两种模式的准备工作不同，不能把两份浏览器参数同时传给同一 Node。

指南中的 `run` 命令会持续运行，终端暂时不再接收输入。保持它打开，称为 **Node 服务终端**；另开一个终端完成第 7 节。不要回来后再启动一次 Node。

## 7. 检查状态并向调用方交付访问文件

在 **Node 设备的新终端**中：

```bash
cd ~/runbridge-node
```

### 7.1 签发一小时访问许可

根据刚才选择的模式，只执行对应的一条：

受管理 Chromium，默认资源 ID 为 `chromium`：

```bash
.venv/bin/runbridge-node grant --config .runbridge/node.json --resource-id chromium --expires-in 3600 --output .runbridge/access.json
```

已有 Chrome，默认资源 ID 为 `chrome`：

```bash
.venv/bin/runbridge-node grant --config .runbridge/node.json --resource-id chrome --expires-in 3600 --output .runbridge/access.json
```

如果你在浏览器 JSON 中自定义过 `resource_id`，这里使用那个完全相同的值。`3600` 是秒数，表示一小时；`--output` 是本次生成文件的位置。

成功会输出“许可 `grant_...` 的对接码已保存：`.runbridge/access.json`”。访问令牌由 Hub 签发，命令自动写入 JSON，不需要你复制登记令牌或手工生成。已有同名文件时命令拒绝签发／覆盖；复用未过期的原文件，或换用 `access-2.json` 并把后续命令中的文件名一并改成相同值。

### 7.2 查询节点与资源

下面从刚生成的身份文件读取真实节点 ID，因此不需要手工抄 ID：

```bash
rb_node_id=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/node.json").read_text())["node_id"])')
.venv/bin/runbridge-node inspect "$rb_node_id" --access-file .runbridge/access.json --output json
```

`rb_node_id` 是当前终端的临时变量；换终端后重新执行这两行。查询结果是一份 JSON，重点看：

| 字段 | 期望值 | 含义 |
| --- | --- | --- |
| `connection_status` | `ONLINE` | 常驻 Node 已连接 |
| `capabilities_stale` | `false` | 能力报告仍有效 |
| `capabilities.resources` 中所选资源的 `readiness` | `READY` | 实际浏览器探测成功 |
| 同一资源的 `occupancy` | `FREE` | 尚未被会话占用，可交付调用方 |

Node 刚启动时可稍等再查。只有 ONLINE、资源列表为空，通常是没有提供浏览器配置；UNAVAILABLE 则按对应模式的排查步骤处理。未准备好前不要把访问文件作为“已可用”的结果交付。

### 7.3 交付文件和资源说明

文件 `.runbridge/access.json` 的格式如下，实际内容由 `grant` 自动生成：

```json
{
  "hub_url": "http://192.168.50.10:8787",
  "node_id": "node_11111111111111111111111111111111",
  "grant_id": "grant_22222222222222222222222222222222",
  "access_token": "EXAMPLE_ONLY_ACCESS_TOKEN_DO_NOT_USE_00000000000000000000000000000",
  "expires_at": "2030-01-01T01:00:00Z"
}
```

上面全部是演示值，时间也不是你签发的实际到期时间。`hub_url` 来自登记时的 Hub 地址；节点 ID 来自身份文件；许可 ID、访问令牌和到期时间来自 Hub 的签发结果。

通过私密文件传输渠道交付**真实生成的 access.json**，并填写这份说明：

```text
访问附件：access.json
Hub 地址：http://192.168.50.10:8787（调用方网络也须能访问）
节点 ID：从 access.json 的 node_id 读取
资源 ID：chromium
浏览器模式：受管理 Chromium
调用方 SDK：Playwright 1.63.0
期限：以 access.json 的 expires_at 为准
操作指南：RunBridge Hub 项目《调用方对接与使用》；Agent 使用其《MCP 浏览器接入》
```

已有 Chrome 时把资源 ID 改为 `chrome`、模式改为“已有 Chrome”，还要告诉调用方它应操作的**已打开页面的精确 URL**。网页地址用于选页，不是浏览器的调试端点。MCP 只使用受管理资源；需要时一并转交 Hub 部署者提供的实际 MCP 地址。

访问 JSON **没有 `resource_id` 字段**，所以资源 ID 必须在交接说明中另外写清楚。不要自己往 JSON 追加字段。调用方只拿访问文件；`node.json`、登记文件、浏览器配置和本机调试端点留在你的设备。

到这里首次部署完成。保持 Node 服务终端运行，再由调用方按 Hub 项目手册完成第一次浏览器连接。后续状态查询、撤销和续期见[状态与许可管理](../user-guide/快速开始.md)，已有 Chrome 的持续画面按[画面采集](../user-guide/浏览器画面采集.md)启用。

## 8. 网络和长期运行

Node 主动连接 Hub，通常不需要开放本机入站端口。本机 Chrome 的 `127.0.0.1`／`[::1]` 调试端点保留在设备上。

如果环境代理误拦局域网 Hub，先正常停止原 Node，再以对应模式加上绕过项重启。以已有 Chrome 为例：

```bash
cd ~/runbridge-node
NO_PROXY=192.168.50.10,127.0.0.1,localhost no_proxy=192.168.50.10,127.0.0.1,localhost .venv/bin/runbridge-node run --settings node.yaml
```

把演示 IP 改成实际 Hub 地址，浏览器模式由 YAML 确定。使用 HTTPS 时保留证书验证。浏览器访问业务网站的代理由浏览器配置决定，与 Node 连接 Hub 的代理不同。

前台终端关闭后 Node 会停止。需要长期运行时，用目标环境的进程管理器固定部署目录、Node CLI 的绝对路径、Node.js 路径和日志。SSH 非交互 PATH 可能不同；先核实全局 uv／Node.js 的实际路径，再写入服务环境。

## 9. Ubuntu 中文字体（按需）

中文截图要求**浏览器所在的 Node 机器**为运行浏览器的用户提供覆盖目标语言的字体。字体和字体缓存由操作系统及设备管理员管理，本项目不安装字库；按 [Ubuntu 字体说明](https://help.ubuntu.com/community/Fonts)或目标系统的官方文档准备。

DOM 中文正确而截图出现方框时，检查该用户的字体与语言设置。环境调整后由所有者正常重启浏览器，并核对真实截图。已有 Chrome 重启会改变浏览器 ID，须重新确认授权端点并更新 `node.yaml`；不要继续沿用旧 ID。

## 10. 停止、备份和升级

先让调用方释放活动会话，再在 Node 服务终端按 Ctrl+C 或使用 SIGTERM 正常停止。已有 Chrome 模式保留浏览器和 Profile；受管理模式确认本次自建 helper 和浏览器退出。cleanup 为 UNKNOWN 时按[排障](运行与排障.md)核查，不清理无关进程。

备份 `node.yaml`、`node.json`，以及所有者需要保留的 Profile／输出。临时断线后复用身份，重启旧 SDK 对象不能恢复，调用方应先确认上次业务效果再申请新会话。

升级时先停止 Node，在原 `.venv` 安装发布者交付的新 wheel；需要已有 Chrome 画面时继续安装 `[visual]`。保留身份和资源配置。受管理运行时锁文件若变化，按模式指南选择新的独立目录准备，并修改 `runtime_directory`。升级后重新查询 ONLINE、READY 和 FREE。

同一设备需要多个 Node 时，按[同机运行多个 Node](同机运行多个Node.md)分别配置身份和资源。

源码安装、构建和同机 Hub／Node 联调见[开发文档](../development/本地开发与联调.md)。
