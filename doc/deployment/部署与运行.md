# RunBridge Node 部署与运行

[文档导航](../README.md) · [Node 配置与凭据](../reference/部署配置与凭据.md) · [运行与排障](运行与排障.md)

适用于 **runbridge-node 0.5.0**。Node 部署在持有浏览器的设备，主动连接另一台机器上已经部署的 Hub。本指南只在 Node 设备安装和操作 Node。

下文 `http://192.168.50.10:8787` 是示例远程 Hub 基址，须替换成 Hub 部署者提供的实际地址。浏览器配置中的回环地址指 Node 设备自身。

## 1. 从 Hub 部署者取得资料

| 资料 | 要求 |
| --- | --- |
| Hub 基址 | 从本设备可达的 HTTP(S) 地址，不能使用本设备的回环地址代替远程服务器 |
| 登记文件 | Hub 部署者提供的同一份一行纯文本 `enrollment.token`，Node 不另生成 |
| 安装包 | 发布者交付的 `runbridge_node-0.5.0-py3-none-any.whl` |
| 服务能力 | 需要 Agent 接入时，确认远程 Hub 已提供 MCP 入口 |

Node 设备需要全局 uv 和标准 CPython 3.14.x（>=3.14,<3.15）；受管理 Chromium 还需要 Node.js >=20 和 npm。已有 Chrome 模式使用本机已授权浏览器，不需要 Node.js/npm。源码开发和同机联调见[开发与联调](../development/本地开发与联调.md)。

先从 **Node 设备**确认远端健康：

```bash
curl --fail http://192.168.50.10:8787/health
```

预期返回 `{"status":"ok","protocol_version":1}`。失败时核对实际地址、路由、防火墙和代理，并联系 Hub 部署者；保留已有 Node 身份。

## 2. 安装 Node 发布包

在 Node 设备创建部署目录，把交付的 wheel 放在其中：

```bash
mkdir -p ~/runbridge-node
cd ~/runbridge-node
uv --version
uv venv --python 3.14 .venv
```

已有 `.venv` 时复用，首次安装才创建。按所选模式选择一种安装目标。

基础 Node（受管理 Chromium 或不采集画面的已有 Chrome）：

```bash
uv pip install --python .venv/bin/python ./runbridge_node-0.5.0-py3-none-any.whl -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

已有 Chrome 且需要持续画面采集：

```bash
uv pip install --python .venv/bin/python './runbridge_node-0.5.0-py3-none-any.whl[visual]' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

`visual` 安装 `browscreen>=0.3.1,<0.4.0` 的正式版本；它用于已有 Chrome，不是受管理 MCP 画面的前置条件。Node 无需 MCP 包或调用方的 Python Playwright SDK。

验证安装：

```bash
.venv/bin/runbridge-node --help
uv pip check --python .venv/bin/python
```

使用设备上的全局 uv 操作本目录的独立环境；虚拟环境内不要求另装 pip。可用 `uv run --no-project --python .venv/bin/python runbridge-node --help` 调用同一环境。如发布者交付本版本的 `deploy-constraints.txt`，安装时增加 `--constraint ./deploy-constraints.txt`；该文件为 requirements 格式的依赖约束。发布包部署无需源码或项目锁文件。

## 3. 放置登记文件并生成身份

仍在 Node 部署目录：

```bash
umask 077
mkdir -p .runbridge
chmod 700 .runbridge
```

将 Hub 部署者交付的文件放为 `.runbridge/enrollment.token`，再执行：

```bash
chmod 600 .runbridge/enrollment.token
.venv/bin/runbridge-node register --hub-url http://192.168.50.10:8787 --enrollment-token-file .runbridge/enrollment.token --config .runbridge/node.json --name office-node
```

保存输出的实际 `node_id`。首次响应 `created=true`；重试使用原身份，成功响应可为 `created=false`。

登记命令先生成私有 `node.json` 再请求远端；文件存在不代表登记成功。网络失败后保留文件，以相同命令重试；不能把它改成另一个 Hub 的身份。后续运行使用此身份，不再依赖登记文件。

| 文件 | 准备方式 | 含义 |
| --- | --- | --- |
| `enrollment.token` | 从 Hub 部署者取得 | 一行登记令牌正文，不加 JSON、引号、`Bearer` 或 `token=` |
| `node.json` | `register` 首次生成 | 稳定 Node ID、名称、所属 Hub 和 Node 专属秘密 |
| `chrome.json`／`playwright.json` | 所有者按所选模式编写 | 本机浏览器授权或启动配置，二选一 |
| `access.json` | `grant` 生成 | 交付调用方的独立访问许可 JSON |

全部内容示例、必填项和参数含义见[Node 配置与凭据](../reference/部署配置与凭据.md)。

## 4. 准备一种浏览器资源

| 选择 | 所有者的操作 | 指南 |
| --- | --- | --- |
| 复用已登录 Chrome | 确认本机授权端点，保存 `chrome.json`；Node 仅借用连接 | [Chrome 复用](../user-guide/Chrome复用快速开始.md) |
| 每会话新建 Chromium | 准备私有 npm 运行时，保存 `playwright.json`；Node 拥有并回收新实例 | [受管理 Chromium](../user-guide/Playwright快速开始.md) |
| 给 Agent 提供受管理资源 | 完成受管理准备，交付资源信息和访问许可 | [MCP 对接准备](../user-guide/MCP对接准备.md) |

浏览器本机库和图形会话须满足所选模式。Chromium 的安装和中文字体在本设备处理；被访问业务地址也必须从本设备的浏览器网络可达。

## 5. 启动、核验并交付许可

按照已经准备的配置，选择一种命令前台运行。

已有 Chrome：

```bash
.venv/bin/runbridge-node run --config .runbridge/node.json --chrome-config .runbridge/chrome.json
```

受管理 Chromium：

```bash
.venv/bin/runbridge-node run --config .runbridge/node.json --playwright-config .runbridge/playwright.json
```

两个浏览器参数互斥；都不提供时只建立控制连接，没有可执行浏览器资源。一个身份只运行一个常驻 Node。

在另一个终端签发许可并查询。下面示例使用受管理资源；已有 Chrome 将 `chromium` 改成其配置中的资源 ID：

```bash
.venv/bin/runbridge-node grant --config .runbridge/node.json --resource-id chromium --expires-in 3600 --output .runbridge/access.json
.venv/bin/runbridge-node inspect node_example --access-file .runbridge/access.json --output json
```

`node_example` 替换为登记得到的 ID。预期 Node `ONLINE`、能力未过期、目标资源 `READY/FREE`。将访问文件和实际资源 ID 交给可信调用方；SDK／HTTP／MCP 调用说明由 Hub 项目维护。

访问文件已存在时复用有效许可或换一个文件名，命令拒绝覆盖。许可文件包含 Hub 地址、节点和许可 ID、访问令牌、到期时间；其 Hub 地址也须从调用方网络可达。Node 身份及本机浏览器配置留在所有者设备。

## 6. 网络、代理与进程管理

Node 主动建立控制、执行隧道及可选画面上传，通常无需向外开放本机监听端口。Chrome 的 `127.0.0.1`／`[::1]` 端点属于本设备，不向调用方公开。

若环境代理误拦局域网 Hub，可对本次 Node 命令设置实际 Hub 地址的绕过项，例如：

```bash
NO_PROXY=192.168.50.10,127.0.0.1,localhost no_proxy=192.168.50.10,127.0.0.1,localhost .venv/bin/runbridge-node run --config .runbridge/node.json --chrome-config .runbridge/chrome.json
```

使用可信 HTTPS／WSS 入口时保持证书验证；不要将网络故障当作身份失效。下载工具可能使用独立代理设置，离线安装需由发布者交付与目标系统匹配的包。

长期运行由自己的进程管理器固定部署目录、身份路径、Node.js 路径和日志。SSH 非交互 PATH 可能不含全局 uv／Node.js；使用核实后的绝对路径，或明确配置进程环境。配置里的相对路径以服务工作目录为准。

## 7. Ubuntu 中文字体

中文显示取决于 **浏览器所在的 Node 机器**。DOM UTF-8 正确但截图出现方框时，先查字库：

```bash
fc-list :lang=zh family
fc-match 'sans-serif:lang=zh-cn'
```

第一条为空说明没有匹配中文字库；第二条可能退到 DejaVu 等不覆盖汉字的字体。字体安装后需要刷新缓存，并由所有者在会话结束后重启测试浏览器，让旧进程的字体缓存更新。

### 有管理员权限：系统字体

在 Ubuntu 上：

```bash
sudo apt-get update
sudo apt-get install fonts-noto-cjk
fc-cache -f
```

这是系统级安装；没有管理员权限时使用下面的用户字体方式。

### 无管理员权限：用户字体

在 Node 部署目录下载字体包到专用目录：

```bash
mkdir -p .runbridge/font-package
cd .runbridge/font-package
apt-get download fonts-noto-cjk
cd ../..
```

只在包成功取得后执行解包。下载遇到旧 APT 代理时可对本次命令使用 -o Acquire::http::Proxy=DIRECT -o Acquire::https::Proxy=DIRECT；直连仍不可达时，从可联网机器下载该发行版的官方包，核对 APT 元数据的 SHA-256 后传入这个目录。使用目标发行版的包版本，并按发行版 APT 元数据核对摘要。

下面的标准库脚本在 Node 部署目录运行：

```bash
.venv/bin/python - <<'PYCODE'
import shutil
import subprocess
from pathlib import Path

root = Path(".runbridge/font-package")
packages = list(root.glob("fonts-noto-cjk_*.deb"))
if len(packages) != 1:
    raise RuntimeError("请提供一份已校验的 fonts-noto-cjk 包")
extracted = root / "extracted"
subprocess.run(["dpkg-deb", "--extract", str(packages[0]), str(extracted)], check=True)
fonts = Path.home() / ".local/share/fonts/noto-cjk"
fonts.mkdir(parents=True, exist_ok=True)
for source in (extracted / "usr/share/fonts/opentype/noto").glob("*.ttc"):
    target = fonts / source.name
    if target.exists() and target.read_bytes() != source.read_bytes():
        raise RuntimeError("已有同名字体不同，请先核对")
    shutil.copy2(src=source, dst=target)
shutil.copy2(src=extracted / "usr/share/doc/fonts-noto-cjk/copyright", dst=fonts / "copyright")
config = Path.home() / ".config/fontconfig/conf.d/70-fonts-noto-cjk.conf"
config.parent.mkdir(parents=True, exist_ok=True)
source = extracted / "usr/share/fontconfig/conf.avail/70-fonts-noto-cjk.conf"
if config.exists() and config.read_bytes() != source.read_bytes():
    raise RuntimeError("已有字体配置不同，请先核对")
shutil.copy2(src=source, dst=config)
subprocess.run(["fc-cache", "--force", str(fonts)], check=True)
subprocess.run(["fc-match", "sans-serif:lang=zh-cn"], check=True)
PYCODE
```

用户字体仅对运行浏览器的这个用户生效。包内语言匹配规则让 zh-CN、zh-TW 分别匹配 SC、TC 字形；没有声明页面语言时可能用同字体集合的其他区域字形，不能据名称含 JP 判断仍缺汉字。

浏览器重启后 CDP 浏览器 ID 会变化，所有者重新确认本机端点并用新配置重启 Node，保留 node.json 和 Profile。完成后验证简体/繁体实际截图，再通过 Node → Hub 订阅 PNG；fc-list 非空或 DOM 文本正确都不能单独证明浏览器已经使用新字体。

## 8. 正常停止、备份与升级

先让调用方释放活动会话，再用 Ctrl+C 或 SIGTERM 正常停止 Node。已有 Chrome 模式保留浏览器及 Profile；受管理模式还要确认自建 helper 和浏览器退出。清理为 `UNKNOWN` 时按[排障](运行与排障.md)核对本次资源，不清理无关浏览器。

备份私有 `node.json`、浏览器配置及所有者需要保留的 Profile／输出。临时断线不重建身份；重启后旧 SDK 对象不能恢复，须由调用方核对上次业务效果再申请新会话。

升级时正常停止 Node，在原 `.venv` 安装交付的新 Node wheel，并保留身份和资源配置；需要画面的部署继续使用 `[visual]`。受管理运行时如锁文件变化，按本项目指南使用新的独立目录准备，再调整 `runtime_directory`。完成后重新检查 `ONLINE` 和 `READY/FREE`。
