# Node 部署与运行

适用于 Node/Hub **0.6.0**。本文所有命令在 **Node 设备**执行。先走完本文；需要复用已有登录时，第 4 步选 borrowed 模式。Node 主动连接已经存在的远程 Hub。

## 1. 取得材料并确认环境要求

向 Hub 部署者或发布负责人取得：

| 材料 | 必须明确的内容 |
| --- | --- |
| Hub 基址 | 如 `http://192.168.50.10:8787`，从本机可达，不以 `/mcp` 或 `/v2` 结尾 |
| 登记文件 `enrollment.token` | Hub 部署者通过自己项目的 `generate-token` 生成、Hub 启动时读取的同一份单行文本 |
| Node 发布包和手册 | `runbridge_node-0.6.0-py3-none-any.whl`、本手册及带注释 YAML 样例 |
| 如需 MCP | Hub 是否启用 MCP，实际入口是什么 |

登记文件是 UTF-8 纯文本，一行 32～256 字符，末尾允许换行。格式示意（不可用于实际登记）：

```text
EXAMPLE_ONLY_ENROLLMENT_TOKEN_DO_NOT_USE_00000000000000000000000
```

不要添加 JSON、引号、`Bearer ` 或 `token=`，也不要自行生成另一个值。将收到的真实文件和 wheel 先保存到 `~/Downloads/`；未收到附件时请向 Hub 部署者补齐。不要把令牌正文直接放入命令行历史。

环境要求为 Python **3.14.x**、可用的全局 uv，以及可运行目标浏览器的系统库、权限和字体。基础工具安装由环境管理员管理，参考 [Python 官网](https://www.python.org/downloads/)、[uv 官网](https://docs.astral.sh/uv/getting-started/installation/)和 [Playwright 系统要求](https://playwright.dev/python/docs/intro#system-requirements)。项目不需要额外 Node.js/npm 环境；Python Playwright 包自带所需 driver。

```bash
curl --fail http://192.168.50.10:8787/health
```

换成真实地址，应看到版本 `0.6.0` 和协议 `2`。`127.0.0.1` 指设备自身，不能用作远程 Hub 地址。

## 2. 安装本项目包与 Python 工具依赖

```bash
mkdir -p ~/runbridge-node
cd ~/runbridge-node
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_node-0.6.0-py3-none-any.whl[playwright]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
umask 077
mkdir -p .runbridge
chmod 700 .runbridge
cp -n ~/Downloads/enrollment.token .runbridge/enrollment.token
chmod 600 .runbridge/enrollment.token
```

`[playwright]` 把项目支持的 Python Playwright **1.63.0** 安装在同一虚拟环境；无需 npm 运行时或 `prepare-runtime`。已装好且版本匹配的库可复用，其他环境中的库不会被本 `.venv` 自动发现。版本不一致时按本发布包的依赖约束处理，避免不同环境互相修改。

`cp -n` 不覆盖已有文件。已有部署复用原身份和原文件，首次部署应使用新的独立目录。

## 3. 准备目标浏览器

managed 模式需要与 Python Playwright 匹配的 Chromium 及系统依赖。浏览器安装与缓存管理遵循 [Playwright 官方浏览器指南](https://playwright.dev/python/docs/browsers)；在**本 `.venv` 的 Python Playwright 环境**准备浏览器。项目不会替你安装系统库或浏览器，也不会在启动时运行下载命令。

已由管理员准备兼容浏览器时可直接使用。默认遵循 Playwright 默认缓存与 `PLAYWRIGHT_BROWSERS_PATH`；独立或共享缓存可通过下步的 `browser_cache_directory` 指定。安装时与运行时必须指向同一缓存。使用 `channel` 或 `executable_path` 的自选浏览器时，由所有者验证其兼容性。

borrowed 模式的已有 Chrome 准备见[已有 Chrome 指南](../user-guide/Chrome复用快速开始.md)，只连接明确授权的本机实例，不另外启动浏览器。该模式仍需要 Python Playwright 库。

## 4. 写一份 YAML，再用一条命令登记并上线

在 `~/runbridge-node` 新建 UTF-8 文件 `node.yaml`，把 Hub 地址改为实际值：

```yaml
config_version: 2  # 仅支持版本 2；省略时默认 2。
hub_url: http://192.168.50.10:8787  # 首次必填，从 Hub 部署者取得；已有身份可省略。
name: office-node  # 默认机器名；只用于首次创建身份。
identity_file: .runbridge/node.json  # 默认此路径；程序自动生成并长期复用。
enrollment_token_file: .runbridge/enrollment.token  # 收到的 Hub 原始登记文件。
tools:
  playwright:
    resource_id: chromium  # 默认 chromium，后续 grant 使用相同值。
    mode: managed  # 默认 managed，每次会话新建浏览器。
    # browser_cache_directory: /absolute/path/to/shared-browsers  # 默认遵循官方缓存环境。
    launch_options:
      headless: true  # 默认 true；有图形桌面时可选 false。
      timeout: 20000  # 本项目启动默认 20000 毫秒，范围 1～30000。
```

YAML 用空格缩进，不用 Tab。相对本地路径以 **node.yaml 所在目录**为基准；不展开 `~` 或 `$HOME`。完整注释与可用字段见[配置样例](../reference/examples/Node启动配置.yaml)和[配置参考](../reference/部署配置与凭据.md)。borrowed 用其指南中的 `tools.playwright` 段替换，不能同时保留 managed 启动选项。

```bash
chmod 600 node.yaml
.venv/bin/runbridge-node run --settings node.yaml
```

首次自动创建私有 `node.json` → 使用登记文件请求 Hub → 探测实际浏览器 → 建立出站连接与心跳。日志出现“节点在线 node_id=… generation=…”。这是前台常驻命令；保持终端，另开终端完成下一步。无需先手工执行 `register`，也无需记录 Playwright 服务端口、浏览器 PID 或版本清单。

首次网络失败会保留已生成身份；修复网络后用**同一份 YAML**重试，不删身份重建。已登记后可移除 `enrollment_token_file` 字段；已有 `node.json` 足以重新上线。保留该字段则重启时幂等确认登记。仅把 YAML 的 `name` 改掉不会改已有身份的名称。

## 5. 签发许可并检查 READY/FREE

在 Node 新终端回到同一目录。以下示例为 managed 默认资源；borrowed 样例资源改为 `chrome`：

```bash
cd ~/runbridge-node
.venv/bin/runbridge-node grant --config .runbridge/node.json --resource-id chromium --expires-in 3600 --output .runbridge/access.json
rb_node_id=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/node.json").read_text())["node_id"])')
.venv/bin/runbridge-node inspect "$rb_node_id" --access-file .runbridge/access.json --output json
```

许可由 Hub 生成，命令保存 `600` 权限 JSON，不会打印秘密。`3600` 表示一小时；不传 `--expires-in` 则无到期时间。`--resource-id` 可重复，省略则许可覆盖该节点全部资源。已有同名输出文件时拒绝签发，需使用未过期的原文件或新文件名。

交付前确认 `connection_status=ONLINE`、`capabilities_stale=false`，所选资源 `readiness=READY`、`occupancy=FREE`。ONLINE 只证明节点连通；UNAVAILABLE 或空资源列表不能当作浏览器可用。启动探测会创建并回收一次专用浏览器，实际任务会话由调用方随后申请。

## 6. 把真实访问文件交给调用方

交付 `.runbridge/access.json`，格式如下（演示值不能使用）：

```json
{
  "hub_url": "http://192.168.50.10:8787",
  "node_id": "node_example",
  "grant_id": "grant_example",
  "access_token": "EXAMPLE_ONLY_ACCESS_TOKEN_DO_NOT_USE_00000000000000000000000000000",
  "expires_at": "2030-01-01T01:00:00Z"
}
```

基址、节点 ID 来自身份；许可 ID、令牌、到期时间来自 Hub 签发结果。`expires_at=null` 表示无期限。JSON 不含资源 ID，所以还需交付以下说明：

```text
访问附件：真实 access.json
Node/Hub：0.6.0；执行协议 2；工具 playwright API 1
资源 ID：chromium
模式：managed，每次新建 Chromium
调用规则：RunBridge Hub 的《调用方对接与使用》或《MCP 浏览器接入》
MCP（若已启用）：Hub 部署者交付的实际 /mcp 地址
```

borrowed 请注明资源 ID、已有页面的精确 URL、该实例已获授权，调用方通过项目 HTTP 操作；MCP 的 `browser_start` 当前只选择 managed。**不交付 node.json、登记文件、本机 CDP 或 Profile**。访问文件经私密渠道传输，由调用方按 Hub 手册完成第一次操作。

## 7. 正常停止、重启与长期运行

先让调用方释放会话，检查 cleanup=COMPLETE，再在 Node 终端 Ctrl+C 或 SIGTERM。managed 回收本次浏览器与 Profile；borrowed 只释放项目连接，原 Chrome、页面、Cookie、localStorage 保留，已经执行的页面修改也会保留。

重启使用同一 YAML、同一身份。不要同时运行两个相同身份。进程管理器配置命令与 YAML 的绝对路径，并保留用户权限、浏览器缓存/代理环境。无需 Node.js 路径，也无需部署目录内的专用 uv。

同机多实例见[多个 Node](同机运行多个Node.md)，故障和升级见[排障](运行与排障.md)。字体、系统依赖与基础工具始终由设备管理员维护。
