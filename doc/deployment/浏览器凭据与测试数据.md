# 浏览器凭据与测试数据

适用于 Node 0.6.0。项目的登记、身份和访问凭据都使用[私有文件](../reference/部署配置与凭据.md)，不调用 macOS 钥匙链、GNOME Keyring 或其他系统凭据库。

## 新建浏览器的存储方式

managed 为每次会话创建独立临时 Profile，释放后删除；它不会自动保存上次登录，也不会导入个人 Chrome 的密码。Node 在 Chromium 启动参数最后补上 `--password-store=basic` 和 `--use-mock-keychain`，分别选择浏览器的本地基础存储、避免 macOS 测试浏览器使用系统钥匙链。即使 `ignore_default_args` 过滤了 Playwright 默认参数，这两个参数仍会传入，不能通过 YAML 改回系统凭据库。

[Playwright 的 Chromium 默认参数](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/server/chromium/chromiumSwitches.ts)也包含这两个选项。直接运行 Chrome 可执行文件的测试脚本需要自行保留它们；绕开 Playwright 启动时，不会自动继承库的默认参数。项目不要求用户在系统弹窗中批准钥匙链访问。

## 测试数据保存在哪里

被测网站的地址、测试账号和业务输入由测试脚本或调用方管理，可以放在其私有目录，例如 UTF-8 `.runbridge/test-data.json`：

```json
{
  "base_url": "https://test.example.com",
  "username": "test-user",
  "password": "替换为专用测试账号的密码"
}
```

这是测试脚本的数据示例，**不是 Node 配置格式**；Node 不自动读取这个文件，也不提供通用账号仓库。调用方自行读取数据，再通过 `locator.fill` 或 MCP `browser_fill` 填入页面。秘密不写到命令行、日志或公开文档。目录权限 `700`、文件权限 `600`，源码调试时确认私有目录已被 Git 忽略；不要把这类数据加到示例 YAML 或提交中。

浏览器登录产生的 Cookie/localStorage 在该会话 Profile 内，由浏览器维护；managed 释放会话后消失。当前公开方法不提供任意 `storage_state` 导入、持久 Profile 或读取 Node 本地任意文件的能力。

## 已有 Chrome 的区别

borrowed 连接的是已经运行的 Chrome，Node 不能修改它启动时选择的凭据后端，也不会替所有者重启或解锁。专用测试 Chrome 由所有者在启动时配置上述参数和专用 Profile；已运行的实例若触发系统凭据提示，先结束项目会话，再由所有者按其浏览器管理流程处理，不能在 Node 配置中假定参数已经生效。

基础存储不提供系统钥匙链的加密保护，只用于受控的专用测试数据。不要因此将个人浏览器 Profile 改成测试 Profile。借用连接释放时保留原浏览器、页面和登录数据，详见[已有 Chrome](../user-guide/Chrome复用快速开始.md)。
