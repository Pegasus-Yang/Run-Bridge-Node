# Node 代码结构与执行流程

适用于 0.8.0。使用者从[部署手册](../deployment/部署与运行.md)开始，本文用于维护源码与工具适配器。

源码均在 `src/runbridge_node/`：

| 模块 | 当前职责 |
| --- | --- |
| `cli.py`、`startup.py`、`config.py` | YAML 版本 2、路径解析、首次登记及稳定身份 JSON 的保存/复用 |
| `client.py`、`protocol.py` | 节点 HTTP 管理、出站控制连接、代次、心跳与会话消息 |
| `capabilities.py`、`chrome.py` | 安装元数据、Python 运行库信息、已有实例端点校验；不以包已安装冒充资源就绪 |
| `executor.py` | 实际 worker/浏览器探测、每资源会话占用、执行 WS、指令路由、关闭与重启恢复 |
| `runtime.py` | 当前 Python 创建会话 worker、短临时目录、归属记录及清理确认 |
| `worker.py`、`ipc.py` | 长度前缀 JSON 管道、顺序消费、请求去重、有界结果缓存与结构化错误 |
| `tool_contract.py`、`tools/__init__.py` | 版本化方法声明、输入/输出模型和显式工具创建器 |
| `tools/playwright.py`、`tools/dom.py` | Python Playwright 对象表、33 项白名单方法、页面/弹窗策略和固定 DOM 脚本 |
| `worker_visual.py` | managed 的同 Page PNG 发布、选页和过期帧丢弃 |
| `visual.py`、`visual_capture.py`、`visual_worker.py` | borrowed 的可选 Browscreen 隔离采集、原始 target 到项目 Page 的映射 |
| `visual_protocol.py`、`visual_wire.py` | 画面文本与二进制合同 |

## 启动、动作与释放

`run --settings` 读取 YAML，相对路径以文件目录为准。已有身份直接复用；首次登记把原始令牌交给 Hub。探测工具后主动建立控制连接，不在 Node 暴露 SDK 服务端口。

会话请求到达后，executor 预留资源，ToolWorker 用当前 `.venv` 的 Python 启动 worker。worker 的 Playwright 适配器持有真实对象：managed 新建 Chromium/context/page；borrowed 连接所有者指定实例并枚举原页面。对象只以会话范围的引用对外展示。

动作从执行 WS 转给匿名管道；适配器检查目标、唯一定位和参数，再调用库方法。写操作进入库后超时仍可能已发生副作用。已有 Chrome 的鼠标、键盘和表单输入先将明确指定的 Page 切到前台，防止后台页暂停动画帧导致点击持续等待；只读查询和画面订阅不切换前台页。

关闭时先正常关闭自建浏览器或断开借用连接。主进程再检查 PID 创建时间、专用目录及 marker，必要时回收确认属于本会话的进程，确认退出才报告 `COMPLETE`。不能根据 Python 进程已退出直接推断浏览器退出；归属不明报告 `UNKNOWN`。

数据与系统凭据库的边界见[浏览器凭据与测试数据](../deployment/浏览器凭据与测试数据.md)，进程细节见[执行与清理](Playwright执行与会话管理.md)。Node 主进程不执行远程源码；扩展仅增加本地显式适配器及其方法模型，不引入动态反射入口。
