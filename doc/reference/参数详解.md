# Node 参数详解

适用于 0.7.0。首次操作按[快速开始](../user-guide/快速开始.md)执行；完整[带注释 YAML](examples/Node启动配置.yaml)用于保存一个环境的设置。基础工具和浏览器准备参考各自官网。

## 先区分三个文件

| 文件 | 由谁创建 | 用途 |
| --- | --- | --- |
| `node.yaml` | 部署者编写 | 启动设置，交给 `run --settings`；YAML 格式版本为 2 |
| `.runbridge/node.json` | 首次启动自动生成 | 长期身份，含节点令牌；维护命令用 `--config` 选择；JSON 格式版本为 1 |
| `.runbridge/access.json` | `grant` 请求 Hub 签发后保存 | 调用许可，交给调用方；查询/会话命令用 `--access-file` 读取 |

`--config` 不读取 YAML，`--settings` 不读取身份 JSON。文件字段、秘密来源和交付边界见[配置与凭据](部署配置与凭据.md)。

## run 与 YAML 顶层

```bash
.venv/bin/runbridge-node run --settings node.yaml
```

`--settings FILE` 是 `run` 唯一的业务参数，必填；不再混用 Hub 地址、浏览器配置或身份文件 CLI 选项。YAML 顶层如下：

| 字段 | 默认值 | 用途与使用场景 |
| --- | --- | --- |
| `config_version` | `2` | 只支持 2，可省略；不要与身份 JSON 的版本混淆 |
| `hub_url` | 无 | 首次必填，从 Hub 部署者取得 HTTP/HTTPS 基址；已有身份可省略，提供时必须与身份内基址一致 |
| `name` | 本机主机名 | 首次生成身份时的显示名称；用于区分设备，修改 YAML 不会重命名已有身份 |
| `identity_file` | `.runbridge/node.json` | 首次自动生成、以后复用的长期身份；同机多实例必须使用不同文件 |
| `enrollment_token_file` | 无 | Hub 交付的真实单行登记文本路径；首次需要文件或环境变量，已登记且无环境变量时可省略此字段 |
| `tools` | `{}` | 不配置时仅建立控制连接，不提供浏览器；需要执行浏览器操作时必须有 `playwright` 项 |

`--settings` 的路径相对当前工作目录；YAML 内的本地路径，包括默认 `identity_file`，相对 **YAML 所在目录**。路径不展开 `~`、`$HOME` 或 shell 表达式；未知字段、旧顶层 `chrome/playwright` 和旧 camelCase 启动项会被拒绝。

指定登记文件时优先读文件；未指定时读取 `RUNBRIDGE_ENROLLMENT_TOKEN`。显式文件不可读或为空会失败，不会回退。只要提供了登记文件或有效环境令牌，就在启动时幂等确认登记；已有身份、没有登记材料时直接重连。

首次网络失败也会保留已经生成的身份；修复网络后用同一配置重试，不删除身份来重新登记。

## tools.playwright

| 字段 | 默认值 | 用途与使用场景 |
| --- | --- | --- |
| `resource_id` | `chromium` | 当前 Node 对外提供的浏览器资源 ID；许可和会话使用同一个值；borrowed 模式也不会自动改名 |
| `mode` | `managed` | `managed` 每次会话新建浏览器，适合隔离任务；`borrowed` 连接所有者已授权的原 Chrome，适合复用登录 |
| `browser_cache_directory` | 不设置 | managed 的浏览器缓存目录；缺省遵循 `PLAYWRIGHT_BROWSERS_PATH` 或 Playwright 默认缓存；自定义安装缓存时设置 |
| `launch_options` | `{}` | managed 的 Python `chromium.launch()` 选项，见下表；不是 Node 进程参数 |
| `cdp_endpoint` | 无 | borrowed 必填，固定本机 `ws://127.0.0.1:端口/devtools/browser/实际ID` 或 IPv6 回环入口；由所有者确认 |
| `authorization_scope` | 无 | borrowed 必须显式为 `BROWSER_INSTANCE`，表示授权整个实例的所有页面；没有单页授权模式 |

managed 不接受 `cdp_endpoint/authorization_scope`。borrowed 不接受 `browser_cache_directory` 或非空 `launch_options`。Node 复用已有 Chrome 时无法改变它原先的启动参数。

### managed 的全部 launch_options

字段使用 Python Playwright 的 snake_case。未设置时使用表中默认行为；项目只开放以下 13 项：

| 字段 | 默认行为 | 用途与例子 |
| --- | --- | --- |
| `headless` | `true` | 无头运行；有图形桌面且要直接看窗口时设 `false` |
| `timeout` | 项目默认 `20000` 毫秒 | 浏览器启动预算，大于 0 且不超过 30000；不是每条业务动作超时 |
| `channel` | 不设置 | 选择 Playwright 支持的浏览器发行通道，例如 `chrome`；对应浏览器应已准备好 |
| `executable_path` | 不设置 | 选择已有浏览器可执行文件；相对 YAML 目录；自选浏览器的兼容性由所有者确认 |
| `args` | Playwright 默认参数及项目本地存储参数 | 追加参数，例如 `["--lang=zh-CN"]`；项目最后保留 `--password-store=basic` 和 `--use-mock-keychain` |
| `ignore_default_args` | 不忽略 | 按官方规则使用布尔值或字符串列表过滤 Playwright 默认参数；上述项目存储参数仍会显式传入 |
| `chromium_sandbox` | Playwright 默认 `false` | 启用 Chromium sandbox；系统需有相应支持 |
| `slow_mo` | `0` 毫秒 | 逐步观察动作时增加延迟，例如 `100`；不代替动作超时 |
| `proxy` | 无 | 浏览器访问网站的代理，例如 `{server: "http://proxy.example:8080"}`；可带官方 `bypass/username/password` 字段 |
| `env` | 继承进程环境 | 传给浏览器的环境对象；自定义时确认必要系统、显示环境仍可用 |
| `downloads_path` | Playwright 临时目录 | 浏览器下载目录，相对 YAML；不代表项目提供任意文件下载接口 |
| `traces_dir` | 不指定用户目录 | 指定浏览器 trace 目录，相对 YAML；不代表项目开放远程 trace 接口 |
| `artifacts_dir` | Playwright 临时目录 | 指定浏览器产物目录，相对 YAML；不改变调用方的文件访问范围 |

选项具体类型与底层行为见 [Python Playwright launch](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch)。安装 `[playwright]` 已带上匹配 Python 库；Chromium 及系统环境按[官方浏览器说明](https://playwright.dev/python/docs/browsers)准备，项目不重复管理下载流程。

## 按场景选择配置

最简单的受管理 Chromium：

```yaml
hub_url: http://hub.example:8787
enrollment_token_file: .runbridge/enrollment.token
tools:
  playwright: {}
```

`hub.example` 是示例名称，需替换为实际可达基址。有图形桌面并希望看到窗口，只将工具段改成：

```yaml
tools:
  playwright:
    launch_options:
      headless: false
```

使用已安装且兼容的 Chrome 时，可选择 `launch_options: {channel: chrome}`；或显式设置 `executable_path`。这仍是新建专用浏览器，不会复用原 Profile。真正复用登录应按[Chrome 复用手册](../user-guide/Chrome复用快速开始.md)选择 borrowed，并取得明确实例授权。

同机多实例使用独立部署目录最容易保持默认身份路径。例如 `office/node.yaml` 与 `test/node.yaml` 分别生成各自 `.runbridge/node.json`；也可以在同一目录明确指定不同 `identity_file`。不要两个进程共用同一身份，详情见[同机多个 Node](../deployment/同机运行多个Node.md)。

## 登记与许可命令

### register（高级维护）

通常不需要，`run` 已在首次启动时完成登记。独立确认登记时才使用：

```bash
.venv/bin/runbridge-node register --hub-url http://hub.example:8787 --enrollment-token-file .runbridge/enrollment.token
```

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `--hub-url URL` | 必填 | Hub 基址；已有身份必须与该基址一致 |
| `--enrollment-token-file FILE` | 无 | 登记文件；未指定时读 `RUNBRIDGE_ENROLLMENT_TOKEN` |
| `--name TEXT` | 本机主机名 | 首次创建身份的名称 |
| `--config FILE` | `.runbridge/node.json` | 保存或复用的身份 JSON；相对当前工作目录 |

### grant / revoke

```bash
.venv/bin/runbridge-node grant --resource-id chromium --expires-in 3600 --output .runbridge/access.json
```

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `grant --config FILE` | `.runbridge/node.json` | 使用哪个节点身份签发许可；YAML 自定义身份路径时，此处也要选择那个文件 |
| `grant --output FILE` | 必填 | 保存新的访问 JSON，拒绝覆盖；相对当前工作目录 |
| `grant --resource-id ID`，可重复 | 不限制具体资源 | 限定许可范围；不传则覆盖该节点全部资源 |
| `grant --expires-in SECONDS` | 无期限 | 相对于签发时刻的有效秒数，大于 0 且不超过 31536000（一年）；例如 3600 为一小时 |
| `revoke --config FILE` | `.runbridge/node.json` | 撤销时使用的节点身份 |
| `revoke grant_id` | 必填位置参数 | 要撤销的真实许可 ID，来自访问文件的 `grant_id`；会停止相关会话与画面 |

撤销例子中的 `grant_example` 必须换成真实 ID：

```bash
.venv/bin/runbridge-node revoke grant_example
```

## inspect 查询命令

```bash
.venv/bin/runbridge-node inspect node_example --access-file .runbridge/access.json
```

`node_example` 换成身份或访问 JSON 中的真实节点 ID。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `node_id` | 必填位置参数 | 被查询节点 ID，必须在当前访问许可范围内 |
| `--access-file FILE` | 无 | 包含 Hub 基址和访问令牌的访问 JSON，通常使用此方式 |
| `--hub-url URL` | 访问文件中的基址 | 指定查询的 Hub；不使用访问文件时，与 `RUNBRIDGE_ACCESS_TOKEN` 一同提供 |
| `--output json` | `json` | 当前只支持 JSON，普通示例无需重复传入 |

访问文件同时存在时，令牌来自文件；无文件才使用 `RUNBRIDGE_ACCESS_TOKEN`。不要用节点身份令牌替代访问令牌。

## 会话命令

用于维护和快速验证；实际业务动作由调用方通过 Hub HTTP/MCP 提交。

```bash
.venv/bin/runbridge-node session create --access-file .runbridge/access.json
.venv/bin/runbridge-node session get session_example --access-file .runbridge/access.json
.venv/bin/runbridge-node session close session_example --access-file .runbridge/access.json
```

后两条中的 `session_example` 换成 `create` 实际返回的 `session_id`，自动读取示例见[快速开始](../user-guide/快速开始.md#验证一次真实浏览器会话)。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `create/get/close --access-file FILE` | 必填 | 发起会话操作的访问许可；会话归属同一许可 |
| `create --resource-id ID` | `chromium` | 选择 YAML 中配置且被许可授权的资源 |
| `create --tool NAME` | `playwright` | 工具适配器，当前仅支持 playwright |
| `create --request-id ID` | 每次自动生成新 ID | 会话创建的去重 ID；同一创建重试用相同 ID，不同任务用新 ID |
| `create --lease-seconds SECONDS` | `300` | 会话租期，1～3600 秒，还受访问许可到期时间限制 |
| `get/close session_id` | 必填位置参数 | 查询或释放的真实会话 ID |

## 环境变量与帮助

| 变量 | 作用与使用场景 |
| --- | --- |
| `RUNBRIDGE_ENROLLMENT_TOKEN` | 登记秘密备用来源；未设置登记文件时读取，不替代身份令牌 |
| `RUNBRIDGE_ACCESS_TOKEN` | `inspect` 没有访问文件时的访问令牌来源 |
| `PLAYWRIGHT_BROWSERS_PATH` | managed 的官方浏览器缓存位置；YAML `browser_cache_directory` 非空时优先使用 YAML 值 |

代理、桌面等系统环境由设备管理员维护；`launch_options.proxy` 仅影响浏览器上网，不是 Node 连接 Hub 的代理设置。凭据和测试数据保存边界见[专门说明](../deployment/浏览器凭据与测试数据.md)。

根命令及每个子命令支持 `-h` / `--help`，例如 `.venv/bin/runbridge-node session create --help`。旧 `prepare-runtime`、`--chrome-config` 和 `--playwright-config` 已删除；更多失败处理见[常见问题](../user-guide/快速开始.md#常见问题)和[运行与排障](../deployment/运行与排障.md)。
