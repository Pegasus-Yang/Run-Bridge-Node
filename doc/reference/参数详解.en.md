# Node parameter reference

[简体中文](参数详解.md) · English

Applies to **Node 0.8.2**. Start with the [quick start](../user-guide/快速开始.en.md). Copy the [annotated YAML](examples/Node启动配置.en.yaml) for an environment. Follow the relevant vendors' documentation for Python, uv, and browser setup.

## Distinguish the three files

| File | Created by | Purpose |
| --- | --- | --- |
| `node.yaml` | Deployer | Startup settings for `run --settings`; YAML format 2 |
| `.runbridge/node.json` | First startup | Stable identity with device token; standalone `register --config` selects it; JSON format 1 |
| `.runbridge/access.json` | Client after claiming through Hub | Five-field `access_config`; diagnostics use `--access-file` |

`--config` does not read startup YAML; `--settings` does not read identity JSON. See [credentials](部署配置与凭据.en.md).

## run and top-level YAML

```bash
.venv/bin/runbridge-node run --settings node.yaml
```

`--settings FILE` is required and is `run`'s only business option. Do not add separate Hub/browser/identity CLI settings.

| Field | Default | Purpose |
| --- | --- | --- |
| `config_version` | `2` | Only format 2 is supported; independent of identity JSON format |
| `hub_url` | Unset | Required initially; HTTP(S) base URL from the Hub deployer; optional with existing identity, but must match it when supplied |
| `name` | Local hostname | Display name when creating identity; changing YAML does not rename an existing identity |
| `identity_file` | `.runbridge/node.json` | Generate initially and reuse; separate instances need separate identities |
| `enrollment_token_file` | Unset | Original enrollment text from Hub; initial startup requires this or its environment fallback |
| `tools` | `{}` | No browser when omitted; add `playwright` to provide browser execution |

`--settings` is relative to the working directory. Local paths in YAML, including default identity, are relative to the **YAML directory**. No expansion of `~`, `$HOME`, or shell expressions occurs. Unknown fields, old top-level `chrome` / `playwright`, and old camelCase launch options are rejected.

An explicit enrollment file takes precedence over `RUNBRIDGE_ENROLLMENT_TOKEN`; missing/unreadable/empty files fail without fallback. With enrollment material, startup confirms enrollment idempotently. Existing identity without enrollment material reconnects directly. First-start network failure retains generated identity; retry the same configuration after repairing the network.

## tools.playwright

| Field | Default | Purpose |
| --- | --- | --- |
| `resource_id` | `chromium` | Public resource ID; use the same ID for sessions; borrowed does not rename it automatically |
| `mode` | `managed` | New browser per session, or `borrowed` for an explicitly authorized existing Chrome |
| `browser_cache_directory` | Unset | Managed browser cache; otherwise follow `PLAYWRIGHT_BROWSERS_PATH` or Playwright default |
| `launch_options` | `{}` | Managed Python `chromium.launch()` options below, not Node process arguments |
| `cdp_endpoint` | Unset | Borrowed requires a fixed local `ws://127.0.0.1:PORT/devtools/browser/ACTUAL_ID` or IPv6 loopback endpoint |
| `authorization_scope` | Unset | Borrowed explicitly requires `BROWSER_INSTANCE`, covering all pages in the instance |

Managed rejects CDP/scope fields. Borrowed rejects `browser_cache_directory` and nonempty `launch_options`; it cannot change an existing browser's startup arguments.

### Managed launch options

Only these 13 options are exposed, using Python Playwright snake_case names:

| Option | Default behavior | Purpose |
| --- | --- | --- |
| `headless` | `true` | Set false only with a usable desktop |
| `timeout` | `20000` ms | Launch budget, 1–30000 ms; separate from action timeout |
| `channel` | Unset | Prepared browser distribution such as `chrome` |
| `executable_path` | Unset | Custom executable, relative to YAML; owner validates compatibility |
| `args` | SDK defaults plus project storage arguments | Additional browser arguments; project appends `--password-store=basic` and `--use-mock-keychain` |
| `ignore_default_args` | Do not ignore | Boolean or string list per SDK; project storage arguments are still supplied |
| `chromium_sandbox` | SDK default `false` | Requires appropriate system support when enabled |
| `slow_mo` | `0` ms | Extra action delay for observation, not an action timeout |
| `proxy` | None | Browser website proxy, e.g. `{server: "http://proxy.example:8080"}`, with SDK bypass/username/password options |
| `env` | Inherit process environment | Browser environment; retain required system/desktop variables |
| `downloads_path` | SDK temporary directory | Relative to YAML; does not expose arbitrary remote file downloads |
| `traces_dir` | No user-selected directory | Relative to YAML; does not expose a remote trace API |
| `artifacts_dir` | SDK temporary directory | Relative to YAML; does not widen client file access |

See [Playwright launch](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch) for types and backend behavior and the [browser guide](https://playwright.dev/python/docs/browsers) for browser/system dependencies. `[playwright]` installs the matching Python library.

## Scenarios

Minimal managed Chromium:

```yaml
hub_url: http://hub.example:8787
enrollment_token_file: .runbridge/enrollment.token
tools:
  playwright: {}
```

Replace the sample host. To show a window with an available desktop, change only the tool section:

```yaml
tools:
  playwright:
    launch_options:
      headless: false
```

`launch_options: {channel: chrome}` or an explicit executable still creates a dedicated new browser rather than reusing an existing profile. Use [borrowed Chrome](../user-guide/Chrome复用快速开始.en.md) for authorized existing login state.

Separate directories such as `office/node.yaml` and `test/node.yaml` get independent default identity paths. Alternatively explicitly set distinct `identity_file` values. See [multiple Nodes](../deployment/同机运行多个Node.en.md).

## Registration and ownership

### register for advanced maintenance

Usually unnecessary because `run` enrolls on first startup:

```bash
.venv/bin/runbridge-node register --hub-url http://hub.example:8787 --enrollment-token-file .runbridge/enrollment.token
```

| Option | Default | Purpose |
| --- | --- | --- |
| `--hub-url URL` | Required | Must match an existing identity's Hub URL |
| `--enrollment-token-file FILE` | Unset | Otherwise read `RUNBRIDGE_ENROLLMENT_TOKEN` |
| `--name TEXT` | Hostname | Initial identity display name |
| `--config FILE` | `.runbridge/node.json` | Identity JSON, relative to the working directory |

### Ownership is managed by Hub

Node's `grant` / `revoke` commands are removed. Clients claim a whole Node using Hub credentials and renew/release with the original lease token. Do not add Hub claim tokens, users, or lease policy to Node YAML. Defaults are 3600-second leases, maximum 86400 and idle timeout 600, with the last two configured on Hub. See the [Hub lease API](https://github.com/Pegasus-Yang/Run-Bridge-Hub/blob/main/doc/reference/Node使用权租约接口.en.md).

## inspect diagnostics

Optional, using an existing lease. It neither grants ownership nor resets idle time, and is not required to bring Node online.

```bash
.venv/bin/runbridge-node inspect node_example --access-file .runbridge/access.json
```

| Option | Default | Purpose |
| --- | --- | --- |
| `node_id` | Required positional | Actual authorized Node ID |
| `--access-file FILE` | Unset | Five-field access JSON or YAML; usual choice |
| `--hub-url URL` | Access-file URL | Without a file, provide with `RUNBRIDGE_ACCESS_TOKEN` |
| `--output json` | `json` | Only JSON is supported |

With an access file, the token comes from that file. Without it, use `RUNBRIDGE_ACCESS_TOKEN`, never a device identity token.

## Session commands

Maintenance and quick checks; business actions use Hub HTTP / MCP:

```bash
.venv/bin/runbridge-node session create --access-file .runbridge/access.json
.venv/bin/runbridge-node session get session_example --access-file .runbridge/access.json
.venv/bin/runbridge-node session close session_example --access-file .runbridge/access.json
```

Replace `session_example` with the actual create result. The [quick start](../user-guide/快速开始.en.md#verify-a-real-browser-session) shows how to read it.

| Option | Default | Purpose |
| --- | --- | --- |
| `create/get/close --access-file FILE` | Required | Same lease that owns the session |
| `create --resource-id ID` | `chromium` | Configured and authorized resource |
| `create --tool NAME` | `playwright` | Current supported tool adapter |
| `create --request-id ID` | New automatic ID | Reuse for retrying the same creation; use a new ID for a new task |
| `create --lease-seconds SECONDS` | `300` | 1–3600 seconds, also bounded by access expiry |
| `get/close session_id` | Required positional | Actual session ID |

## Environment and help

| Variable | Purpose |
| --- | --- |
| `RUNBRIDGE_ENROLLMENT_TOKEN` | Enrollment fallback when no file is set |
| `RUNBRIDGE_ACCESS_TOKEN` | `inspect` token only when no access file is supplied |
| `PLAYWRIGHT_BROWSERS_PATH` | Managed browser cache; YAML `browser_cache_directory` takes precedence |

Device administrators maintain proxies and desktop environment. `launch_options.proxy` affects browser website traffic, not the Node-to-Hub connection. See [browser credentials and test data](../deployment/浏览器凭据与测试数据.en.md).

Each command accepts `-h` / `--help`, e.g. `.venv/bin/runbridge-node session create --help`. Old `prepare-runtime`, `--chrome-config`, and `--playwright-config` are removed. See [common problems](../user-guide/快速开始.en.md#common-problems) and [operations](../deployment/运行与排障.en.md).
