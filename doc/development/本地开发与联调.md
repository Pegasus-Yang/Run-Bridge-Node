# Node 本地开发与联调

仅面向开发者，用户部署见[部署手册](../deployment/部署与运行.md)。在独立源码目录使用根 `.venv`：

```bash
uv sync --extra playwright --extra visual -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python -m pytest tests -q
uv build --wheel --out-dir dist -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

基础 Python/uv/浏览器准备遵循相应官网；项目测试不替代系统安装。真实 worker 测试显式启用，并让当前环境找到已准备的匹配浏览器缓存：

```bash
RUNBRIDGE_RUN_BROWSER_TESTS=1 .venv/bin/python -m pytest tests/test_playwright.py -q
```

此测试创建自己的 worker、Chrome、短临时 Profile 和业务夹具，验证正常关闭、worker 强制退出、driver 异常及 borrowed 释放后原页面/Cookie/localStorage 保留。不要使用已有登录 Profile。

直接启动 Chrome 的测试夹具必须保留 `--use-mock-keychain`、`--password-store=basic`，不靠批准系统钥匙链弹窗使测试继续。borrowed 用例还应创建前后台两个页面，确认指定后台页输入/点击成功，释放后两页均保留。测试网站账号与业务输入放在忽略的私有文件中，Node 不自动加载此类文件。

跨机器验收使用新 wheel、新部署目录、新身份和独立 `.venv`，Hub 部分由 Hub 开发手册维护。Node 应主动连接测试指定的 Hub，不启动原部署，不复用原 token 或数据库。共享安装缓存只读；结束时按 PID 创建时间和专用 Profile 确认只清理本次进程。

工具适配器位于 `tools/`，通用 worker 使用 ToolError、结构化命令、有限队列和结果缓存；新增工具需在显式创建器、配置与能力探测、两端方法合同中登记，不能开放任意 exec/eval。实际所有权与清理见[worker 架构](../architecture/Playwright执行与会话管理.md)。
