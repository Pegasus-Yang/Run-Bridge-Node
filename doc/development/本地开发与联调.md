# Node 本地开发与联调

[文档导航](../README.md) · [用户部署指南](../deployment/部署与运行.md) · [调用方联调](调用方联调.md)

本文面向 Node 开发者。正常用户在浏览器设备安装发布 wheel 并连接远程 Hub；源码依赖、构建、回归和同机调试集中在本目录。

## 1. 准备源码环境

在 Node 源码根目录：

```bash
uv sync --locked --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv run --locked --no-sync runbridge-node --help
```

需要研究已有 Chrome 画面时改用 --extra visual 同步。Hub 和 Node 各保留自己的虚拟环境，不把另一个项目作为内部包依赖。

## 2. 本机联调前提

需要同机同时启动两端时，将 Hub 和 Node 源码放在相邻目录，按 **Hub 项目 doc/development/本地开发与联调.md** 启动本地开发 Hub，再在本项目根目录操作：

```bash
uv run --locked --no-sync runbridge-node register --hub-url http://127.0.0.1:8787 --enrollment-token-file ../runbridge-hub/.runbridge/dev-enrollment.token --config .runbridge/dev-node.json --name dev-node
uv run --locked --no-sync runbridge-node prepare-playwright --runtime-dir .runbridge/playwright
cp -n doc/reference/examples/Playwright节点配置.json .runbridge/dev-playwright.json
uv run --locked --no-sync runbridge-node run --config .runbridge/dev-node.json --playwright-config .runbridge/dev-playwright.json
```

这里只对同机开发使用回环 Hub 和相邻目录；远程部署使用服务端交付的基址与文件。使用独立 dev-* 配置和数据库，不复用日常身份争抢连接。

真实 SDK、会话和画面订阅回归样例放在[开发联调](调用方联调.md)，用户的接口集成文档由 Hub 项目维护。

## 3. 构建并交付 Node 包

```bash
uv build -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv export --locked --no-dev --no-emit-project --no-hashes --format requirements-txt --output-file deploy-constraints.txt
```

当前 wheel 为 dist/runbridge_node-0.5.0-py3-none-any.whl。画面部署导出约束时增加 --extra visual。Node wheel 必须包含 server.mjs、package.json、package-lock.json；浏览器缓存和 node_modules 不随 Python 包交付，用户通过 prepare-playwright 准备。

修改 Browscreen 范围或锁文件时，在本项目开发环境解析、同步和验证，再交付新包及约束。范围内接受稳定 0.3.x 不代表每个版本均有实机验收。

### 同版文档包和交付检查

Node 所有者还需要安装、登记和模式指南，wheel 不包含这些文档。源码和文档提交后，从该发布提交制作独立文档包：

```bash
git archive --format=tar.gz --prefix=runbridge-node-docs/ --output=dist/runbridge-node-docs.tar.gz HEAD README.md doc
```

解压后根目录为 `runbridge-node-docs/`，其中含 `README.md`、`doc/` 和公开示例；不打包 `.venv/`、`.runbridge/` 或私有调试目录。`git archive` 读取的是已提交的 HEAD，不含未提交修订，交付前核对它与 wheel 来自同一次发布。

将本项目 wheel、文档包和可选的同版依赖约束一起交付，并告知用户如何下载或接收。首次部署验证应在源码目录外新建真实 `.venv`，使用 wheel 安装，确认包从该环境的 `site-packages` 导入；不要以项目原 `.venv` 的通过结果替代全新安装验证。

## 4. 测试

基础配置合同：

```bash
uv run --locked --no-sync pytest -q tests/test_config.py
```

完整回归：

```bash
uv run --locked --no-sync pytest -q
```

Node 回归可能使用已安装的浏览器／运行时创建临时真实进程，按实际测试夹具前提准备。测试引用的独立客户端样例位于 doc/development/examples/，其指南是开发联调文档，不依赖用户部署步骤中的代码片段。

测试进程可通过下表显式选择已准备的环境，先确认所选 Node.js 的 `--version` 可以正常返回；这些是测试参数，不会改写用户部署配置。

| 环境变量 | 用途 |
| --- | --- |
| `RUNBRIDGE_HUB_PROJECT` | 相邻 Hub 源码位置，默认使用 `../runbridge-hub` |
| `RUNBRIDGE_NODE_BINARY` | 受管理测试使用的 Node.js 绝对路径，默认从 PATH 查找 node |
| `RUNBRIDGE_PLAYWRIGHT_RUNTIME_DIR` | Node 私有 npm／浏览器运行时，默认 `.runbridge/playwright` |
| `RUNBRIDGE_CHROME_BINARY` | 已有 Chrome 测试使用的独立浏览器二进制 |
| `RUNBRIDGE_TEST_EVIDENCE_FILE` | 测试输出的脱敏 JSON 证据路径 |

原始设计、协议实现和历史验收见维护者导航；机器专属资料保存在共享工作区的私有 local/，不随用户文档分发。
